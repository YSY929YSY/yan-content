## T1 · 候选里 20% 的中文是繁体（🔴 落库前必修）

### 现象

M1 产出的 1851 条里，**368 条（20%）的中文是繁体**：

```
明日暇？    → 明天有空嗎？
次は誰？    → 下一個是誰？
今寝て。    → 現在睡。
子供好き？  → 喜歡小孩嗎？
```

Tatoeba 的 `cmn_sentences.tsv` 混了简繁，而「言」通篇是简体。

### 这不是新问题，仓库里早就有解

`tools/tatoeba-align.py:35`：

```python
_T2S = opencc.OpenCC("t2s")
```

上一轮做日中对齐时处理过，**M1 的新脚本没接上**。照它的用法接即可。

### 关于「以后要支持繁体」的口子

**不要在内容层分叉存两份。** 原则和 `glossEn` 一样：

> **一个 token / 一句话，多种呈现。内容层存规范值（简体），繁体是显示层的转换。**

而且候选里**已经存了 `tatoeba.zh_sentence_id`** —— 任何时候都能回到原句。
所以「口子」已经在了，**不用新增字段**。以后要繁体是渲染时 `s2t`，一个开关的事。

### 验收

- 重跑后 1851 条里繁体字命中 **0 条**（用一个繁体常用字集做机器自检，别靠眼看）
- `tatoeba.zh_sentence_id` 保持不变 —— 转换的是显示文本，不是来源标识
- 日语原句**一个字都不许动**
- 脚本仍只读语料、只写 `staging/`

## T3 · 对齐行的 gloss 收窄

### 现象

真机上：

```
カード → 积分卡/银行卡，卡片   （10 字，撑成两行、把列拉宽）
見せる → 给……看，展示        （7 字）
```

对齐**没坏**（「宾语」仍在 `を` 正下方），但**辅助行喧宾夺主**了 ——
而完整释义本来就显示在卡片顶部。

`SOUL.md` 视觉身份规则：辅助信息不能抢主信息的位置。

### 要做的

对齐行的 gloss **再收一层**：在已有的「只取第一个义项」基础上，
**再取到第一个分隔符为止**（`，`、`、`、`/` 之类），并**不换行**。

预期效果：

```
カード → 积分卡      （而不是 积分卡/银行卡，卡片）
見せる → 给……看     （而不是 给……看，展示）
袋    → 袋子        （不变）
現金  → 现金        （不变）
```

**判据**：对齐行是**提示**，不是定义。定义在卡片顶部，用户抬眼就能看到。

### 硬规则

- ❌ **不许截断成半个词**再加省略号 —— 学习产品里截断的词义比没有更糟
- ❌ 不改词条本身的 `meaning_zh` —— 只改**对齐行怎么显示**
- ❌ 不改 `TokenColumnSentence` 的三槽位结构（B9-2 刚做对，别退回去）
- 收窄逻辑要有测试：给一批真实 `meaning_zh`，断言输出长度和不截断半个词

### 顺带验一件事（不用改）

`app.json` 是 `orientation: portrait`，**所以转屏测试本来就不会变**。
真正会撑散对齐的是**系统字号**（代码没设 `allowFontScaling`，RN 默认跟随系统）。
报告里写清楚：这一条**只能真机验**，标「待验证」，不要写成已验证。
