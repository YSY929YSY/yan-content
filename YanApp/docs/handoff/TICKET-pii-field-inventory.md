## 背景：分层的轴选错过一次

早先的判断是「照片/手账 vs 学习进度」，理由是"照片更敏感"。**这个轴是错的。**

法规上的轴是「**敏感个人信息 vs 一般个人信息**」（PIPL 第 28 条）：

- **一张风景照不因为是图像就敏感**
- **但「照片 + 精确位置 + 时间」的组合是行踪轨迹，明确列举为敏感**
- **照片里的 GPS EXIF 本身就是行踪轨迹**
- 学习进度/生词口袋是**一般个人信息**，
  《促进和规范数据跨境流动规定》第五条第四项对不满 10 万人有明确豁免

**门槛完全不同**：一般个人信息 <10 万人免予三大出境机制；
**敏感个人信息没有完全豁免**，不满 1 万人也要标准合同或认证。

已经查到的（复算命令见验收）：

```
schema.sql:108,141          lat / lng（多张表）
schema.sql:177-178          exif_lat / exif_lng      ← 专门存照片 GPS
schema.sql:201-202          travel_checkins 上有 (user_id, lat, lng) 索引
schema.journal.sql:82-83    手账 lat/lng
schema.moments.sql:17       moments lat/lng
src/features/world/exifImport.js   主动读取照片 GPS
```

**所以只把照片挪到境内 OSS 是白挪的** —— 表里还留着坐标，轨迹照样出境。

## 要做的

### 1. 逐字段盘点，产出一张表

对 `src/lib/schema*.sql` 里**所有会同步到 Supabase 的表**，逐字段列出：

| 字段 | 所在表 | 是否可识别到个人 | 敏感判定 | 判定依据 | 当前位置 | 是否出境 |
|---|---|---|---|---|---|---|

**敏感判定只用三档**，并写明依据：

- `敏感·行踪轨迹` —— 精确经纬度、GPS EXIF、可拼出连续位置的时间戳组合
- `一般` —— 可识别到个人但不属于第 28 条列举
- `非个人信息` —— 与自然人无关

**判不准的写「判不准，原因是 X」，不要硬归类。**

产出 `staging/pii-field-inventory.md`。

### 2. 单独标出「拿掉坐标就不敏感」的字段

这是最有价值的一列：哪些字段**只要去掉精度或不出境，整条数据就从敏感降为一般**。

例如：`travel_checkins` 若只保留城市级网格（`schema.journal.sql:68` 提到过
按 0.1° 约 11km 取整的做法），是否还构成行踪轨迹？**给出判断和依据，不要下结论说"这样就安全了"。**

### 3. EXIF 现状

`exifImport.js` 读了照片 GPS 之后：

- 写进了哪几个字段？
- **上传到 Supabase Storage 的图片文件本身，EXIF 有没有被剥掉？**
  （这是最容易漏的一条 —— 表里剥干净了，图片文件里还带着）
- 给出可复算的验证方法

### 4. 一般个人信息的人数口径

《促进和规范数据跨境流动规定》的豁免按「当年累计向境外提供的人数」算。
**给出现在这个数怎么统计**（不是统计结果 —— 我们几乎没有用户），
以及将来接近阈值时靠什么监测。
