## 本轮决策指标（5-4）

**两个消费点里，`（…）` 与句子其余部分字号相同的处数：2 → 0**

「两个消费点」= 词卡词场中文行 + 复习卡的 `ask`。
两处都要改，**只改一处不算完成**——`REPEATED-MISTAKES.md` 第 1 条的形状就是
「一处改了、另一条真实路径没走到」，已经发生过 4 次。

## 这张工单把主线推迟多久

**约半轮。** 它不推进词场条数，但它是 ZH 54 那批括号能不能留住的前提：
负责人同意加括号的条件就是「字体调小」。**不做这张，那 4 条括号是全字号裸露的。**

## 背景

`（…）` 里是**日语按惯例省略、中文必须补出来**的成分（`DECISIONS.md` 判据一）。
它是**注**，不是句子的一部分，所以要在视觉上退后一层。

当前只有 4 条带括号（#10 #15 #19 #45），其中 **#19 一句两个括号**，是最重的样本。

## 要做什么

1. 把中文句按 `（…）` 切成片段，括号内的片段用更小字号 + 更低对比度渲染，
   **括号本身也一起降级**。
2. 两个消费点都接上：
   - 词卡的词场中文行
   - 复习卡的提问面（`src/features/review/units.js:199` 把 `f.sentence.zh` 当 `ask`）
3. 切分逻辑写成**纯函数 + 单元测试**，放在 `src/features/wordbank/` 下，
   两处共用同一个函数。**不要在两处各写一份正则**（`AGENTS.md` 开头：一条规矩有两处写法就一定会漂开）。

## 🔴 硬约束

1. **不改内容包。** 这轮一个字的中文都不动。
2. **fail closed**（不变量 4）：句子里没有 `（）`、括号不成对、嵌套、或空括号 —— 
   一律**原样整句显示**，不要试图猜。
3. 半角 `()` **不处理**。内容里的是全角 `（）`，半角括号可能是中文原文的一部分。
4. 新增测试必须放在 `__tests__/` 下（不变量 10）。
5. 不顺手重构，不拆 `App.js`（不变量 5、6）。

## 验收

1. `npm test && npm run typecheck && npm run audit`
2. **变异验证**（逐条写明「改坏什么 → 哪条测试红」）：
   - 把 fail-closed 分支改成「括号不成对时也切」→ 必须有测试转红
   - 把两个消费点之一的调用去掉 → 必须有测试转红
3. **决策指标前后值：2 → 0。** 说明清楚这个数是怎么点的（哪两处、怎么确认接上了）。
4. **真机/预览看一眼 #19**（`（我）听到有人叫（我的）名字。`）在**词卡**和**复习提问面**
   上各长什么样，把两张图或两段描述写进报告。

   > ⚠️ 这一条是这张工单存在的真正理由。#19 在复习卡上是**提问面**——
   > 用户看中文回想日语。括号在词卡上是注，在提问面上可能变成「提示的一部分」。
   > **纸上推不出来，必须看。**
   >
   > 看完如果提问面明显别扭：**不要自己改规则**，写进报告交负责人定
   > （备选方案是「一句只标一处」，但那要回头改内容包，是另一张工单）。
