## 为什么机械规则不用再加了

上一轮抽查：我在工单里点名的 4 条，规则抓到 4 条；你和 GPT 点名的 4 条，抓到 2 条。
**能机械抓的已经抓完了。**

两个漏网都指向同一处：

```
n5_fun  もう５分待とう。/ 我还要等五分钟。   → 判为 DATA
        「待とう」是意向形 =「再等五分钟吧」,当前中文语气全错
```

它有数字解析问题，所以判了 `DATA`，`FIX_ZH` 就没机会了。数据佐证：

```
DATA 里还带其他信号的:  1 条
reasons >= 2 的:        1 条
LAND 里 chinese_signals 非空的:  0 条
```

**不是问题少，是一条命中就停了；而中文这一维基本没被检查过。**

## 要做的

### 1. 五状态改成多标签（必需，但只是前置）

一条句子可以同时是 `DATA` + `FIX_ZH`。改成每条带一个标签数组，
`review_status` 保留为「最高优先级动作」但不再吞掉其他信号。

改完给出：**有多少条其实带 ≥2 个标签**（当前只有 1 条，这个数应该会明显上升）。

### 2. 中文错译率（这一轮的唯一交付物）

从 **LAND 301 条**里抽 **40 条**，人工逐条判读中文。

- 抽样必须可复现（沿用脚本的确定性排序，写明用了什么）
- **40 条全部贴进报告**，每条给：日文 / 现有中文 / 判为对还是错 / 错在哪（一句话）
- 判据分三类，分别计数，**不要合成一个数**：
  | 类 | 例 |
  |---|---|
  | 意思错 | `姉→姐妹`、主语错、`待とう→我还要等` 语气错 |
  | 意思对但不像人话 | 「我姐妹是一个很棒的打字员」 |
  | 意思对、也通顺，但和日语语体对不上 | 口语句译成公示语（`便后请洗手`） |
- 给出总错译率 `?/40`

**这一轮不改任何一条中文。** 只出数。

### 3. 顺带记一笔来源风险（一句话即可）

中文来自 Tatoeba 的 zh 对齐句，那是**用户贡献**的，质量不齐。
如果错译率高，问题在源，不在筛选规则 —— 在报告里写明这一点，
**别把它描述成"我们的规则没做好"**。
