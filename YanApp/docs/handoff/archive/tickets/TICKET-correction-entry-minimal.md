# 工单 · 纠错入口（最小形态，本地 only，不做积分）

> 先读 `AGENTS.md`（第五节报告规矩、第六节交报告前必做）。
> **本轮不碰内容包、不碰服务端、不做积分。**

## 这张工单把主线推迟多久

**约半轮。** 但它是主线的**供给侧**：现在每发现一条质量问题都要等一轮 AI 测量
（`た→田`、`頭痛い`、「打头教头」全是这么抓到的），而负责人在真机上一眼就能看出来。
这个入口把他的判断变成数据。**这是唯一能持续供给主线的机制。**

## 明确的产品决定（不要改）

- **要显式入口，不要长按。** 负责人原话：「不然没人知道长按是纠错」。
  长按是隐藏手势，发现率接近零。
- **不做积分/会员/兑换。** 理由：现在还没有会用它的人。
  规则设计、防刷、账务全是成本，而产品验证才稀缺。**有人真的提交了纠错，再谈奖励。**
- **不做服务端。** 本轮只写本地文件。

## 要做的

### 1. 入口位置

词卡详情页**底部**一个低权重的文字按钮：**「去纠错」**。

- 参照现有的同类入口（`App.js` 里 `分账` 那种低权重次级入口的样式），不要新造视觉
- **不喧宾夺主**（`SOUL.md` 视觉身份规则）：不用主色、不加图标强调、不放在首屏视线中心
- 词卡以外的地方**不加**（例句、词场、首页都不加）

### 2. 表单：三个选项 + 一个可选输入框

点开后是一个轻量弹层，**不要跳页**：

```
这条哪里不对？
  ○ 中文意思不对
  ○ 日语不自然
  ○ 例句和这个词对不上
  [可选]  想补一句说明…
  [提交]  [取消]
```

- 三个选项**不许增减**。多了没人选，少了分不出类型。
- 说明框可留空，提交按钮不因为空而禁用。
- 提交后一句确认（「记下了」），**不要弹感谢、不要动画、不要计数**。

### 3. 落盘

写本地 JSONL，一行一条，追加：

```json
{"ts":"2026-08-26T12:34:56Z","wordId":"n5_atama","word":"頭","reading":"あたま",
 "kind":"meaning|unnatural|example_mismatch","note":"","appVersion":"…"}
```

- 用项目现有的本地存储方式（**先读现有代码怎么做的，不要新引依赖**）
- **不发网络请求。** 不上报、不同步、不进内容包。
- 写失败要 fail closed：提示「没记上」，不要假装成功

### 4. 一个只读导出脚本

`scripts/corrections-export.mjs`：读本地 JSONL，按 `kind` 和 `wordId` 汇总，打印到 stdout。
**只读，不写文件，不改内容。**

## 明确不做

- ❌ 不做积分、等级、会员、兑换、任何激励
- ❌ 不做服务端、不上报、不同步
- ❌ 不碰 `assets/content.fallback.json` / `yan-content/content.v2.json`
- ❌ 不加长按手势
- ❌ 不在词卡以外的页面加入口
- ❌ **不许根据纠错自动改任何内容** —— 它只是记录，改不改是人的决定
- ❌ 不拆 `App.js`（不变量 5）；改动限制在词卡详情那一段
- ❌ 不构建、不发 OTA（本轮改的是 JS，走热更新，**但由负责人决定什么时候推**）

## 不变量

照 `AGENTS.md`。特别相关：

- **不变量 7**：用户可见文案不出现内部状态词。按钮写「去纠错」，不写 `report` / `flag` / `draft`
- **不变量 4 fail closed**：写盘失败 = 明确告诉用户没记上
- **不变量 10**：新增测试放 `__tests__/`

## 验收

- 报告顶部有「异常自查」（5-2）；数字附复算命令（5-1）
- 有测试覆盖：提交后 JSONL 多一行、三种 `kind` 都能写、写失败时不报成功
- 截图或渲染测试证明入口是**底部低权重**，不是主色按钮
- `npm test && npm run typecheck && npm run audit`，贴原始输出
- `git status --short` 干净

## 做完写哪里

`ACTIVE.md` + `CC-REPORT.md` 追加新一节。

**验收的真正标准不在这一轮**：负责人自己用一周，看一周点几次。
**点不到三次，这个功能就该删掉。** 在报告里写明这一条，别让它变成没人用还留着的装饰。
