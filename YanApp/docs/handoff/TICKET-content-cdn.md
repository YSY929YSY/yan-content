# 工单 · 内容包改走境内 CDN（ContentAdapter，第一层抽象）

> 先读 `AGENTS.md`（第五节 5-1~5-6）与 `docs/china-launch/README.md` 的 D4/D5。
> **本轮不碰内容包的内容，只改「从哪里拉」。不改同步链、不改词场/gloss。**

## 本轮决策指标（5-4）

**大陆网络下，内容包首字节时间与完整下载时间：现状 → ?**

现状：首字节约 6 秒，完整下载一两分钟（8MB，走 `raw.githubusercontent.com`）。
**这个体验下，就算备案办下来、上架了，留存也是零。**

不是"接通了 CDN"，是**那两个时间数**。

## 这张工单把主线推迟多久

**不推迟。** 它与备案、与个人信息合规**都无关**（内容包是静态词库，不含个人信息），
是纯体验项，技术风险最低，可以最先做完。

## 背景

App 顶部长期显示「当前使用离线内容」——那不是 bug，是这个原因。
`fallbackToCacheTimeout: 0` 让启动直接用旧包、新包后台下载，
而下载在大陆网络下几乎完不成。

## 要做的

### 1. 抽出 `ContentAdapter`（这一层比换 CDN 本身更重要）

把「内容包从哪里拉」收敛成一个可配置的适配层，**不要在业务代码里散着写 URL**。

- 源可配置：`cn`（阿里云 OSS + CDN）/ `global`（现有 GitHub raw）
- **选源依据不要用当前 IP** —— 用户出国、用 VPN 时 IP 会变。
  用构建变体或用户的 `home_region`（**`home_region` 本轮不实现，先留接口**）
- **两个源必须能拉到同一份内容**：加一道校验，
  两源的 `_meta.version` 与内容 sha256 不一致时**明确报错，不许静默用旧的**

### 2. 迁到阿里云 OSS + CDN

复用馋了现有的阿里云账号与 OSS（同一主体 `浙ICP备2026053105号`）。

- 内容包是**公开静态资源**，不含个人信息，**不需要鉴权**
- 发布链要跟着改：`scripts/push-content.sh` 现在推到 `origin/main`，
  **新增一步推到 OSS**。⚠️ **两个源必须同时更新**，
  否则就是 2026-08-22 那次「两份文件不一致」的重演
- 发布闸门 `tools/check-content-release.sh` **要能检查 OSS 上那份**
  与 `develop/v2` 提交一致（上一轮刚修好磁盘 vs 提交，这次是再加一个源）

### 3. 实测两个数

**必须是真实网络下的实测，不是估算。**

- 大陆网络：首字节 / 完整下载，迁移前后各一次
- 给出测量方法（`curl -w` 的时间分解即可），负责人要能自己复跑

拿不到大陆网络就说拿不到，**不要用估算数字填决策指标**。

## 验收

- 异常自查（5-2）；数字附复算命令（5-1）
- **决策指标**：首字节 / 完整下载的前后实测值 + 测量方法
- 两源一致性校验有测试：**故意让两源版本不一致 → 必须报错**（变异验证）
- 发布链改动说明：一次发布要推哪几个地方，漏一个会怎样
- `npm test && npm run typecheck && npm run audit`，`git status --short` 干净
