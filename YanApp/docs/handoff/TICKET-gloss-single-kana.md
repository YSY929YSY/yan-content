```
  → 私[我] も[也] と[和/与] て[手] も[也] 楽[舒适] しか[牙科] っ[∅] た[田] です[是]
```


### 根因链（已定位，不用再查）

**F-2 · 我们修过的那个闸门，从来没在设备上生效过。**

`wordFieldAlignment.js:117` 的第四参 `exampleTokens` 决定 `allowedSingleCharSurfaces`；
`singleCharSurfacesFrom` 拿不到数组时返回 `null`，而判断写成
`... && allowedSingleCharSurfaces && !...has(surface)` —— **null 时闸门短路，全部放行。fail-open。**

两个渲染入口 `App.js:125` 和 `App.js:2627` **都只传 3 个参数**。
只有离线脚本和一条合成单测传第四参。

而且它结构上传不了：`EXAMPLE_TOKENS` 按**词条 id** 索引，**词场句没有自己的 id**。

**F-3 · 来源优先级压过最长匹配。** `directCandidateAt`（:83-91）先取 priority 0（`word` 命中）
的最长者，只有一个都没有时才看 priority 1（`reading` 命中）。
所以 1 字的 `word` 会赢过 5 字的 `reading` —— 与 :143-144 的注释相反。
`楽[舒适] しか[牙科]` 就是这个形状。

**F-4 · GRAMMAR 表无条件抢先。** :124-132 把语法表放在链首，不检查同位置有没有更长的真词。
实测 16 处：`と` 遮住 `とても`、`だ` 遮住 `だれか`、`も` 遮住 `もう`。

## 要做的

### 1. 在消费点拦截单假名（不是在候选表）

**判据**：不管候选来自 `word` / `reading` / 辞书形哪条路，
**只要将被消费的那个表面是长度为 1 的假名，就不许作为 wordBank token 命中**，
落到 blank 分支。

- **单汉字保留**（`本→书` `水→水` `手→手` 是真词）
- 依据：跑在句子里的单个假名几乎不可能是实词；真正是词的
  （`が` `を` `は` `の`）本来就在 GRAMMAR 表里

我已经试过两种更浅的位置，供参考（**不要照抄，以你实测为准**）：

| 做法 | 覆盖率 | 残留误命中 | 副作用 |
|---|---|---|---|
| 现状 | 95.98% | 88 个 / 82 句 | — |
| 只禁单假名 `reading` 候选 | 93.04% | 25 个 / 24 句 | 零损失单汉字 |
| 禁所有单假名候选 | 93.38% | 17 个 / 17 句 | 丢了 4 条多字命中（边界副作用） |

**残留的都是辞书形路径漏的**（`て`→`照る`、`し`→`する`），所以要拦在消费点。

### 2. 顺手处理 F-3 / F-4（同一处代码，一起改省一轮）

- **F-3**：跨 priority 也要取最长匹配。`reading` 命中的 5 字词应当赢过 `word` 命中的 1 字词。
  **同长度时保持现有命中顺序**（word → reading → 辞书形）。
- **F-4**：GRAMMAR 命中前，先看同位置有没有**更长的** wordBank 候选；有就让位。
  给出这条改动影响了多少 token。

**这两条都要有独立测试**，且写明变异验证（改坏什么 → 哪条转红）。

### 3. 修 F-6：覆盖率闸门量的是「非空」不是「正确」

`wordFieldAlignment.test.mjs:112-134` 的判据是 `if (row.zh?.trim()) covered += 1`，
所以 `た[田]` 全部计入 covered。

**当前 95.98% 里有约 5.3 个百分点来自明确错误的 gloss；
把它们算作空洞是 90.63%，低于 95% 闸门。这条 ★★ 测试是被错误输出撑到及格的。**

改成两条独立断言：

- **单假名 wordBank 命中数 = 0**（硬断言，这是新的质量底线）
- 覆盖率下限：**按修复后实测值减一个小余量**设定；
  **不许沿用 95%**（修复后达不到），也**不许设成 0 或远低于实测**（那等于没有守卫）
- 报告写明实测值、设定的下限、余量为什么取这个值

### 4. 修 F-5：那条「设备条件」断言是恒真的

`src/lib/__tests__/glossFullBankWiring.test.mjs:17-19`：

```js
const expected     = buildWordFieldAlignment(sentence, fullBank, dictionaryForms);
const deviceResult = buildWordFieldAlignment(sentence, fullBank, dictionaryForms);  // 同一个表达式
assert.deepEqual(deviceResult, expected);   // 恒真
```

同文件的 `notDeepEqual` 变异守卫和四条源码正则是**有效的**，保留。
但这条以「设备条件」命名的 `deepEqual` 没有构造任何设备条件 —— **删掉或改成真的断言。**

另：那四条源码正则**只覆盖 `WordBankScreen` 一个入口**，
`App.js:1888-1906`（`WordBookShelfScreen` 里的 `<WBDetailPage>`）没有任何覆盖。
当前它恰好传全库，但改成子集不会有任何测试转红。**补上。**
