## 要做的

### 1. 换句（16 条有备选的）

对每个有备选的 anchor，按**原选句规则**从剩余候选里取次优：
`unknown_word_count` 最小 → `member_word_ids` 最多 → 7–12 字优先 → `jp_sentence_id` 最小。

**换上来的句子必须重新过一遍已有的机械判据**（负面动词、外国度量衡、
中文信号、难度信号），命中就继续往下取。全部候选都命中 → 归入"无可用备选"。

### 2. 新句子仍要人判

换上来的 16 条**不能自动认为合格** —— 机械判据只能排除已知形状。

把换后的句子按外部审核那份格式导出到
`staging/jp-22-swapped-for-review.md`（沿用 `staging/land-301-for-review.md` 的
指令头和表格格式），交给负责人走同一条外部审核流程。

### 3. 独苗 6 条 + 无可用备选的，单独列清单

给出 anchor / 现有句 / 为什么不行 / 备选池为什么用不了。
**这批不落库，也不改句子** —— 它们是唯一可能需要人写日语的部分，由负责人决定。

### 4. 顺带补管线的去重（本轮做）

`scripts/wordfield-shortlist.mjs` 从来没检查过「这个 anchor 是不是已经有词场」。
343 条里 11 条与现有 20 条重叠，落库那轮撞上了 7 条。

加一道过滤：**候选来源里排除 `wordBank` 中已有非空 `wordField` 的 anchor**。
用字段判断，不要硬编码 id。给出过滤掉多少条。


### 5. 补回被丢掉的词场成员（落库轮欠账）

落 167 条那轮，成员匹配用的是**词面直接对照**，活用形匹配不上就被丢了。
抽查结果：

```
167 条里 13 条成员被丢；members 为空的 2 条、只有 1 个的 48 条
  n5_go_2   期望1 实得0 | トルコ語を習ってるんだ。   （習う → 習ってる）
  n5_neru   期望1 实得0 | 普段より遅く寝たんです。   （遅い → 遅く）
  n5_chuu   期望4 实得2 | 彼は昨日、一日中働いた。
  n5_gatsu  期望4 实得3 | 今日は三月五日です。
  n5_atsui_3 期望3 实得2 | あの厚い本を読んでたの？
复算：见 CC-REPORT 本轮一节
```

**空 members 等于落了两条不成立的词场** ——
`docs/content-standard-wordfield.md:43`：「词场 = 这个词真实出现时，**身边站着哪些词**」，
成员是词场的定义本身。

**解法在同一个仓库里已经有了**：`wordFieldAlignment.js` 的 `dictionaryFormsFrom()`
能把 `習ってる → 習う` 还原（Map size 1083）。成员匹配接上它即可。

要做的：

- 成员匹配改为「词面直接命中 **或** 经 `dictionaryFormsFrom` 还原后命中」
- **只补成员，不改任何句子**
- 回填这 13 条到内容包（**这一步改内容包，需要内容窗口**；
  如果本轮其余步骤不改内容包，把回填单独做成窗口内最后一个 commit）
- 给出：补回后 members 为空的还剩几条（**应该是 0**；不是 0 就逐条解释）

### 6. 测试守卫改成分基线，不要排除（落库轮欠账）

`1d88230` 把 gloss 守卫改成 `if (field?.sentence?.jp && !field.source)` ——
**带 `source` 的一律跳过**。这件事报告里披露了（CC-REPORT 3301 行），不是隐瞒。

但判据有问题：**今后所有新增词场都会有 `source`**，
所以这个守卫现在覆盖 20/187，将来覆盖 20/N，**永远绿**。
`CLAUDE.md` 第 3 节：「一个永远红的检查等于没有检查」—— 永远绿的同理。

改成两条基线：

- **legacy（无 source）**：保持现有 `133/133` 严格断言，不许放宽
- **Tatoeba（有 source）**：先实测当前 167 条的 gloss 覆盖，
  把实测值**减一个小余量**设成下限，跌破就红

**不许把下限设成 0 或设得比实测低很多** —— 那等于没有守卫。
报告里写明实测值、设定的下限、以及余量为什么取这个值。
