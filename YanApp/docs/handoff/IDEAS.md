# YanApp · 灵感停车场

> 新想法先记录，不自动成为当前工单，也不打断 `ACTIVE.md`。

## 使用规则

每个想法回答：

- 想法是什么？
- 它解决用户的什么问题？
- 与“学 → 用 → 记住经历”有什么关系？
- 可能影响哪些数据结构？
- 是否涉及不可逆迁移或当前地基？
- 下一次评审时间？

只有以下情况可以打断当前工单：

- 当前实现会使新想法以后无法兼容；
- 涉及不可逆的数据迁移；
- 当前基础方向有证据表明错误；
- 存在用户数据或内容真实性风险。

## 已记录

### I1. 自动化来源审计流水线

- 问题：内容反复经历“生成 → 发现错误 → 再找源 → 再修改”；
- 方向：claim 拆分、来源家族、确定性校验、subagent 反例、自动裁决、staging patch；
- 状态：已进入路线图，但尚未实施；
- 与当前任务关系：先建立 publication 边界，再实施流水线。

### I2. 外部模型审核包

- 问题：豆包、Kimi、DeepSeek 没有仓库文件权限或稳定 API；
- 方向：导出 claim JSON，导入 evidence JSON；外部模型永不直接修改正式文件；
- 状态：source-audit 稳定后再做；
- 不作为第一版流水线依赖。
