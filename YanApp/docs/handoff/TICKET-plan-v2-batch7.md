## B7-1 · 删掉口袋的解释文案

**现状**：`收入口袋` 按钮下面挂着两行小字：

```
收进来后会进入复习，之后还会再问你。
已存本机，联网后同步
```

**要做的**：删掉第一行，**保留第二行**。

**为什么删第一行**：口袋已由项目负责人决定冻结（见 `DECISIONS.md`「口袋冻结」）——
它不改到期、不改题型、不保存上下文，和「会了/一般/忘了」语义重叠。
功能都冻结了，不该再占两行去解释它。而且那句话对**没入袋**的词同样成立，本身就没说清什么。

**为什么留第二行**：`已存本机，联网后同步` 是离线时的**诚实状态**，属于 fail-closed 的一部分。
删了就变成「假装同步成功」—— 那是这个项目栽过四次的形状。

- 文件：`App.js`（`收入口袋` 按钮附近）
- 验收：离线入袋仍显示同步状态；`npm run audit` 无新 WARN

## B7-2 · 修词性标签的尺寸

**现状**（真机截图）：`名词` / `动词` 后面那个灰色椭圆比文字大一大圈，
向左溢出到文字外面；而 `名词（する动词）` 又是另一个尺寸。

**要做的**：让灰底跟着文字走（内边距固定、不要固定宽高），三种长度的词性标签视觉一致。

- 文件：`App.js` 的词详情页词性标签样式
- **不要**顺手改其它样式常量（`AGENTS.md` 不变量第 6 条）
- 验收：`名词` / `动词` / `名词（する动词）` 三种长度下灰底都贴合文字

## B7-3 · 词场标签自解释 + 成员高亮

**现状**：词场那一段的标签是「一起出现」，下面一句日语。
`探す` 的词场是「安いお弁当を探します。」，成员是 `安い` + `お弁当`。

**问题**：标签没说清**谁和谁**一起出现。用户直接问了「什么叫一起出现」。

**要做的**：

1. 把**成员词在句子里高亮**（`安い`、`お弁当` 视觉上标出来）——
   数据现成：`wordField.members[].id` 能查到词条，词条有 `word` 和 `reading`
2. 标签改成能自解释的措辞。**措辞按 `SOUL.md` 的中文语感规则**，不要写成说明书

**背景**（`docs/content-standard-wordfield.md` 第三节）：词场是「用一个句子，不用一个格子」——
不并列近义词，而是造一句话把相关的词框在一起。做成并列词块试过一次，失败了。

- 文件：`App.js` 词详情页的词场渲染段
- **不改 `units.js`、不改内容包**
- 验收：20 条词场里随便点开三条，成员词都被正确标出；成员词在句中找不到时**不报错也不乱标**
  （`auditWordFields` 已经保证成员必然出现在句子里，但渲染层仍要 fail safe）

## B7-4 · 例句逐词中文对齐（**只做 20 条样板**）

### 要做成什么样

项目负责人的原始需求（真机批注，`レシートをください` 那条）：
把日语 token 和它对应的中文**上下对齐**，下面再给一句语序正常的中文。

```
レシート     を        ください
小票        （宾语）    请给我
─────────────────────────────
请给我小票。                      ← 现有的 exampleZh，不动
```

**价值**：`レシート` 在日语句首、`小票` 在中文句尾 —— **中日语序是反的**，
而现在的呈现把这个差异藏起来了。对中文母语者，语序恰恰是最大的障碍。

### 已经量过的覆盖率（抽样 400 句 2590 token，别重新量）

| 类别 | 占比 | 解法 |
|---|---:|---|
| 助词 / 标点 | 37% | 固定表 |
| 词库直接查到 | 30% | 查 `wordBank` 的 `meaning_zh` |
| 查不到 | 33% | 见下三类 |

查不到的三类，**都有解**：

1. **活用碎片**（`飲ん` / `咲き` / `がっ` / `て`）—— Sudachi 切成了词干+词尾。
   `scripts/build-example-tokens.py` **本来就产出辞书形，只是没存**
2. **助动词**（`です` / `ます`）—— 属于语法成分，进固定表，不查词库
3. **表记差异**（`ください` vs 词库里的 `下さい`）—— **按 `reading` 查**就能对上

### 本轮的范围（不要越界）

**只做 20 条词场句的样板**，不碰 4400 条例句。

**先不改管线**：先只用「词面查 + `reading` 查 + 语法成分固定表」看能到多少。
够用就停；不够再谈要不要重跑 `build-example-tokens.py` 存辞书形——
**那是下一张工单的事**（`AGENTS.md`：不许顺手扩范围）。

### 硬规则

- **查不到就留空，不猜。** 不许用 LLM 补中文 —— 那是 `pedagogical_content`，
  不能由模型直接进内容（`DECISIONS.md`「多源与人工的边界」）
- 逐词中文是**派生数据**，不写进内容包，运行时算或放 `staging/`
- 语序正常的那句中文**用现有的 `exampleZh`，不重写**
- 中文那一行是**辅助**，不能喧宾夺主（`SOUL.md` 视觉身份规则）

### 验收

- 20 条词场句都能渲染出对齐行
- **报告里给出实际覆盖率**：多少 token 有中文、多少留空
- 留空的 token 不显示占位符、不报错
- `npm test && npm run typecheck && npm run audit` 全绿
