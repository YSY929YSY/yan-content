# 工单 · gloss 查词必须用全库 + 「不用再问我了」改成图标

> 先读 `AGENTS.md`（第五节 5-1/5-2/5-3/5-4）。
> **本轮不碰内容包、不落库、不开内容分支。**

## 本轮决策指标（5-4）

**设备真实条件（按词书过滤的 wordBank）下的 gloss 覆盖率。**

不是全库条件下的 96.29% —— 那个数守不到设备上。
**这一轮要拿到的是「用户实际看到的覆盖率」，修复前 → 修复后。**

## 这张工单把主线推迟多久

**不推迟。** 主线是词库深度，而这个 bug 让 200 条词场在设备上显示错误的 gloss。

## 根因（已定位，不用再查）

`App.js:1614`：

```js
const bookWords = (content.wordBank || []).filter(w => (w.levels || [w.level]).includes(activeBook.level));
// → wordBank={bookWords}  传进 WordBankScreen
```

`fieldTokenColumns(sentence, wordBank)`（`App.js:124`）拿到的因此是
**当前词书的子集**，不是全库 8005 条。

真机实测（N4 词书，`店員にサイズを聞きます。`）：

| token | 设备显示 | 全库应为 | 原因 |
|---|---|---|---|
| `サイズ` | 留空 | 尺寸 | N1，不在 N4 书 |
| `袋` | 留空 | 袋子 | N3 |
| `現金` | 留空 | 现金 | N3 |
| `聞き` | **心情** ❌ | 听 | `聞く` 是 N5，不在 N4 书 → 辞书形还原失败 → 贪心切成 `聞`+`き` → `き`→`気`→心情 |

**这和 2026-08-25 抓到的 `scopedInputs` 是同一个形状**：
缩小查词范围 → 第三级辞书形命中通路关闭。**第三次了。**

## 要做的

### 1. gloss 查词改用全库（根因修复）

`fieldTokenColumns` / `readingForFieldToken` 必须拿到**完整 `content.wordBank`**，
与「当前词书是哪本」无关。

- **不要改 `bookWords` 本身** —— 词书过滤对列表、进度、复习池都是对的，
  只有 gloss 查词不该用它
- 建议：把全库沿 props 或 context 单独传下去，命名要能看出意图
  （例如 `glossLookupBank`），**不要复用 `wordBank` 这个名字**，
  否则下一个人还会接错

### 2. 补一条「设备条件」的测试（这条比修复本身更重要）

现有基线守卫（`__tests__/wordFieldAlignment.test.mjs`）传的是**全库**，
所以它在这个 bug 存在时**一直是绿的**。

**一个测不到真实调用条件的守卫等于没有守卫**（`CLAUDE.md` 第 3 节）。

新增测试：**按词书子集**构造输入，断言 gloss 结果与全库一致。
把 `店員にサイズを聞きます。` 在 N4 子集下的结果作为回归样本 ——
**修复前这条必须红**（做完在报告里写明"改坏什么 → 哪条转红"）。

### 3. 决策指标：设备条件下的覆盖率

对 200 条词场，**按每条 anchor 所属词书的子集**跑一遍 gloss，给出：

- 修复前：设备条件覆盖率 `?%`（对照全库 96.29%）
- 修复后：应与全库一致
- 差距最大的 10 条，列出来

### 4. 「这个词不用再问我了」改成右上角图标

现状：词卡底部有两条灰色小字叠着 ——
`这个词不用再问我了` 和 `去纠错`。是加纠错入口时没考虑已有元素造成的。

**决定（负责人已定，不要重新讨论）**：

- **保留功能**（`handleGrade('mastered')` 是 SRS 的逃生口，删了用户要点好几轮「会了」）
- **改成词卡右上角一个图标**，参照常见做法
- **不要做成滑动手势** —— 隐藏手势没人发现（负责人否掉长按纠错时是同一个理由）
- 底部只留 `去纠错` 一条

图标要有**可读的无障碍标签**，文案说人话，不出现内部状态词（不变量 7：
不写 `mastered` / `retire`）。
