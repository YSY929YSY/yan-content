## 问题

现有词条页把词头、释义、词场、裸 `coreChunk`、例句、声调和评分平铺成资料卡。
其中 `coreChunk` 只有日文，既没有中文/英文释义，也没有来源级别，不能作为“常用搭配”主内容。用户看得见信息，却不容易连成“这个词在一句话里怎样用”。

参考体验的价值不在颜色、社交人数、笔记按钮或可编辑词义，而在阅读顺序：词义之后先给一条可读、可听、可复述的完整例句；假名、罗马音、中文连续呈现。

## 产品决定与范围

1. 主例句只有一条 canonical 输入：`exampleJp + exampleRoma + exampleZh + EXAMPLE_TOKENS[id]`。
2. 顺序固定为：词头/词义 → **主例句（日文逐词假名 → 罗马音 → 中文）** → 补充内容 → 评分。
3. 裸 `coreChunk` 不再用“搭配/常用搭配”标题出现在主学习面；没有 `jp + zh` 结构化释义就不展示。它不是删除内容，而是停止把未解释片段当作已可学习的用法。
4. 暂不做句中目标词高亮：`～回 → 三回`、活用等不能靠字符串猜。以后由 P2-2 添加明确 span/target token 后再做。
5. 暂不新增例句、中文翻译、搭配释义、语法说明、相关词/反义词、笔记、慢速/循环播放或社交功能。
6. 声调沿用现有来源印证提示和显示逻辑；不新增声调数据或改变声调判据。

## 不涉及来源的部分

本工单只使用既有的例句字段和本地派生 token；不生成、不改写内容，因此不产生新的内容 claim。

## 必须等待 P2-2 来源流水线的部分

- `usage` / 常用搭配的中文释义；
- 目标词在例句中对应的 span；
- 反义词、词组、语法说明、相关词；
- 新例句或既有例句的真实性、翻译正确性再核验。

P2-2 才启用自动化候选/独立反证/结构验证流程。subagent 只能输出候选和 evidence JSON，不能直接写内容包或升级 publication。
