## 已拍板

### D1 · 分层的轴是「敏感 vs 一般」，不是「照片 vs 进度」

PIPL 第 28 条列举的是**行踪轨迹**，不是"图像"。
风景照不因为是图像就敏感；**照片 + 精确位置 + 时间的组合是轨迹**，GPS EXIF 本身也是。

门槛完全不同：

- 一般个人信息，当年累计不满 **10 万人** → 免予安全评估 / 标准合同 / 认证
- **敏感个人信息没有完全豁免** —— 不满 1 万人也要标准合同或认证

**已查到言的实际情况**（比先前判断严重）：

```
schema.sql:108,141          lat / lng（多张表）
schema.sql:177-178          exif_lat / exif_lng
schema.sql:201-202          travel_checkins 上有 (user_id, lat, lng) 索引
schema.journal.sql:82-83    手账 lat/lng
schema.moments.sql:17       moments lat/lng
features/world/exifImport.js  主动读照片 GPS
```

**推论：只把照片挪到境内 OSS 是白挪的** —— 表里还留着坐标。

### D2 · 豁免的是申报机制，不是保护义务

哪怕落进 10 万人豁免，以下仍然要做（且都是低成本的前端/文档工作）：

- 跨境**单独同意**（不能混在隐私政策的一揽子同意里）
- 告知境外接收方名称、联系方式、处理目的与方式、信息种类
- 个人信息保护影响评估（PIA）并留存三年

### D3 · 不做「为了备案而代理」的网关

境内 ECS 代理 Supabase **不消除数据出境**，只增加延迟、故障点和运维面。
让阿里云资源承担**本来就该在境内做的真实功能**（内容包、媒体、STS 凭证、版本检查）。

### D4 · 现在做抽象层，不做迁移；不砍功能

**理由**：真正贵的不是搬数据（零用户，没有数据），是决定**数据边界**和**账号归属**。
想清楚之后换后端是机械劳动。

- 先做 `ContentAdapter` / `MediaAdapter` / `DataAdapter` / `AuthAdapter`
- `home_region` **注册时确定，跟账号走** —— **不要用当前 IP 判断**
  （用户出国、用 VPN 时 IP 会变，数据会漂）
- 云同步、照片、手账**功能一个不砍**

### D5 · 顺序

```
1. 修完同步链          ← 已完成
2. 内容包迁境内 CDN     ← 与合规无关的纯体验项,技术风险最低
3. 字段级盘点          ← 不知道哪些字段敏感,就没法决定迁什么
4. 抽象层 + home_region
5. 按盘点结果决定迁什么
6. 隐私政策 + 单独同意 + PIA
7. 备案（填报此时是真实的）
8. 大陆区上架
```

1. **日语学习 App 是否被归入「教育类」** —— 工信部 APP 备案通知要求教育类
   提交主管部门审核同意文件。**这一条如果成立，会卡在最前面，所以要最先问。**
   建议原话：
   > 「个人主体的非经营性日语自学工具，是否按教育类处理？
   > 如按教育类处理，所需前置审批文件是什么？个人主体是否可申请？」

   （**Apple 侧允许个人 IAP 是明确的**，这是另一层问题）
