## 3. 新调研中真正有价值的部分

只保留能进主线的，其余不评价。

### 3.1 词书 ↔ 场景双向联动：**成立，但真正的工作量在内容不在代码**

- 代码侧：`tags.scene` 字段已存在、`units.fromScenePhrase` 已存在、`origin` 已存在 → 反向（场景 → 复习）**已经通了**。
- 缺的是正向（词 → 它出现在哪个场景）和真实标注：**168 条有效场景标签 / 8005 条**，其中便利店 23 条、地铁 14 条。
- 结论：联动不是新架构，是**给一个场景的 30–40 个词打真标签 + 给该场景每句加 `core_vocab: [wordId]`**。这是内容工单，一两天的量，不是重构。

### 3.2 轻量口袋：**值得做，但只做数据层**

- 它的价值不是"云朵的口袋"，是给用户一个**自己攒的、比 8005 条小得多的集合**，让词书页第一屏不再是大词典。
- 最小实现：一个存储键 + 入袋动作 + 词书默认视图切到它。入袋的词直接进现有 SRS（`unitKey('word', …)` 不变，**不加前缀**，否则进度归零）。
- 不做：云朵动画、表情、成长、装饰。

### 3.3 主动输出题：**值得做，且成本被高估了**

关键发现：`units.js` 的 `mode: 'produce'` 单元（ask=中文情境，answer=日文原句）**已经有 85+ 条**（场景句 69 + 地铁 16 + 深卡骨架）。
"选词拼句"可以完全建在这些已有单元上——把 `answer` 打散成词块 + 干扰项，**零新增内容字段**。
这是本轮性价比最高的一项：一道真测验，把整个产品从"自评"推到 active recall。

### 3.4 综合挑战：**现在不做**

前提是"至少两个场景成熟"。当前一个都不成熟。放 P1 末或 P2。

### 3.5 英日优先模式：**P2，且只做白名单**

片假名 ≠ 英语原词（假朋友、非英语来源）。当前 `verified` 只有 2 条的情况下，再开一个需要逐条判断的字段是负债。价值也没被验证过——没人测过用户是否真的想要。

### 3.6 云朵：**只保留为表现层，且本轮不动**

功能叫"口袋"就够了，不需要云朵才能存在。等闭环验证成立后，再决定云朵是虚拟形象的皮，还是替代它。**这条需要你裁决，不能两个都做。**

### 3.7 调研里我不采纳的

- "三场景 72 小时生存战 MVP"：三倍内容量，与"打透一个"直接矛盾。
- "N5-N1 完整词书作为学习主线"：8005 条里 6642 条是机器稿，把它当主线等于把用户推进未精修区。词书是仓库，`publication.learning` 才是学习边界。
- "AI 生成脚本直接入库"：违反已生效的发布契约。

## 4. 当前最小闭环定义

> **一句话**：用户在便利店场景遇到一个词 → 收进口袋 → 当天/隔天被要求**拼出**那句话 → 答错能看见这句话出自哪个场景。
> 首页今日任务、SRS、三 Tab、场景句进复习 —— **这四样已经有了，P0 不重做、不重构。**

### P0-1 场景词绑定（内容侧）

- **目的**：让"这个词我在便利店见过"成为数据事实，而不是文案说法。
- **改哪里**：`assets/content.fallback.json`（+ 同结构的远端内容包）；`scripts/validate-content.js` 加一条校验；`src/lib/contentSchema.ts` **不动**（新增字段是可选的，形状闸门无需改）。
- **范围**：便利店场景 10 句 + 2 段 miniDialogue，每句加 `core_vocab: [wordId]`；把涉及的 30–40 个词的 `tags.scene` 从 `daily` 改成真实值。
- **验收**：`core_vocab` 里每个 id 都能在 `wordBank` 里查到（校验脚本机器拦，仿 `auditWordFields`）；`convenience` 场景词 ≥ 30 条；不新增任何未在 `publication.learning` 里的词进学习路径。
- **用户能感知什么**：暂时感知不到 —— 这是 P0-2/P0-3 的前置，**必须在同一阶段内完成到 P0-3**，否则这一项就是"看着厉害的活"。

### P0-2 词书默认视图 = 口袋 / 场景词

- **目的**：词书 Tab 打开不再是 8005 条大词典，第一屏是"你自己的词"。
- **改哪里**：`App.js` 的 `WordBankScreen`（约 1509–1700 行）**只改默认视图与筛选项**；新增纯函数 `sceneWordsOf(wordBank, sceneId)` 放 `src/features/wordbank/`。
- **不做**：不拆 `App.js`（工作包 5 是独立的事，不许顺手做）。
- **验收**：口袋为空时显示场景词入口而不是空白；已有的"全部/未学/学习中/已掌握"筛选保持可达；进度键格式零改动。
- **用户能感知什么**：打开词书不再被 8005 条淹没。

### P0-3 口袋（遇词入袋）

- **目的**：给用户一个自己攒出来的集合，并让它直接产生复习。
- **改哪里**：`src/lib/storage.js` 登记一个新键；场景页/词卡加一个入袋动作；`useHomeSummary` 只读不写地多显示一个数字。
- **约束**：入袋的词进 SRS 时 **沿用裸键 `词-读音`**，不加前缀。
- **验收**：入袋 → 杀进程 → 重开仍在；入袋的词次日出现在今日任务；`writeGuard` 挡住写入时界面不会显示成"已入袋"。
- **用户能感知什么**：点一下，这个词就是我的了，明天它会来找我。

### P0-4 一种主动输出题：选词拼句

- **目的**：把复习从"我觉得我会"变成"我拼对了"。
- **改哪里**：新增纯函数 `src/features/review/produceChoices.js`（输入一条 `mode:'produce'` 单元 → 输出词块 + 干扰项）；`ReviewScreen.js` 加一个渲染分支。
- **范围**：只对 `mode: 'produce'` 的单元启用（场景句/地铁句/深卡骨架，现成 85+ 条）；`recall` 单元维持自评不变。
- **验收**：纯函数有测试（含"干扰项不能与正确词块重复""句子只有 1 个词块时降级回自评"）；答错记入 `lapses` 走现有 `srs.js`，评分逻辑一行不改。
- **用户能感知什么**：第一次在这个 App 里"答错"，并且知道自己确实还不会。

### P0-5 复习卡回到场景

- **目的**：让复习不是孤立的卡片，而是"你在便利店那句里见过它"。
- **改哪里**：`ReviewScreen.js` 把已有的 `origin` 字段做成可点；跳转到对应场景并定位到那一句。
- **验收**：`origin` 缺失时不显示按钮（不显示假入口）；跳转后能返回复习队列且当前进度不丢。
- **用户能感知什么**：忘了的时候能回到"我当时在哪见过它"。

**这五项都是增量：不新建页面、不新建 Tab、不拆 `App.js`、不依赖完整 IP、不依赖完整数据治理。**

## 8. 给 Codex / Claude Code 的任务拆分

> 通用约束（每个任务都适用）：**不许顺手重构**；不改 `srs.js` 评分逻辑；不改进度键格式；不拆 `App.js`；单 commit 可 `git revert` 回滚；不下载新数据源；LLM 产出只能是 candidate，不能直接写进 `publication`。

### T1 · 便利店场景词绑定（纯内容 + 校验，不动 UI）

- 范围：`assets/content.fallback.json` 的 `scenes[convenience]` 与相关 `wordBank` 条目；`scripts/validate-content.js`。
- 做：每句加 `core_vocab: [wordId]`；把该场景涉及的 30–40 词 `tags.scene` 从 `daily` 改为 `convenience`（保留 `daily`）；校验脚本新增"`core_vocab` 的 id 必须存在于 `wordBank`"。
- 不做：不动其他 5 个场景、不动地铁、不改 `contentSchema.ts`。
- 验收：`node scripts/validate-content.js` 通过；`convenience` 场景词 ≥30；无新词被加入 `publication.learning`。
- 回滚：单 commit revert，内容包回到当前版本。

### T2 · 场景词选择器（纯函数 + 测试，不接 UI）

- 不做：不接任何页面。

- 回滚：删文件即可，零影响面。

### T3 · 口袋存储 + 词书默认视图

- 范围：`src/lib/storage.js`（登记新键）、新增 `src/features/wordbank/pocket.js`（纯函数）、`App.js` 的 `WordBankScreen` 默认视图与一个入袋按钮。

- 不做：不加前缀键、不改五本词书入口、不动 `useHomeSummary` 的写路径（它只读）。

- 回滚：单 commit revert；新键残留在磁盘上无害（读不到就是空）。

### T4 · 选词拼句题型

- 范围：新增 `src/features/review/produceChoices.js` + 测试；`ReviewScreen.js` 一个渲染分支。
- 做：把 `mode:'produce'` 单元的 `answer` 切成词块，生成 2–4 个干扰项（干扰项从同场景词里取，不用 LLM）。
- 不做：不改 `units.js`、不改 `srs.js`、不对 `recall` 单元启用。
- 验收：纯函数测试含"词块唯一"、"干扰项不与正确块重复"、"只有 1 块时降级回自评"；答错走现有 `lapses`；`recall` 复习行为逐像素不变。
- 回滚：单 commit revert，复习页退回自评。

### T5 · 复习卡回场景

- 范围：`ReviewScreen.js` + `App.js` 的场景跳转挂接点。
- 做：`origin` 可点 → 跳到对应场景并定位那句。

- 验收：`origin` 为空不显示按钮；跳转后可返回且复习队列位置不丢。
- 回滚：单 commit revert。

**建议顺序**：T1 → T2 → T3 → T4 → T5。T4 可以与 T3 并行（互不碰同一文件），但 T5 必须最后。
