# 言（YanApp）大陆上架 · 现状与待决策

> 写于 2026-08-30。**这份是给外部顾问看的，不需要读过本仓库其他文档。**

## 一、这是什么产品

日语学习 App，个人开发者作品。技术栈 **Expo / React Native（iOS 为主）**。

- 已在**海外区** App Store 上架 2 个版本
- **从未在中国大陆区上架**（因为没有 ICP 备案号）
- **真实用户约等于零**：只有开发者的几个朋友下载过

## 三、需要决策的三件事

### 决策 1 · 用户照片和手账是否要迁到境内

大陆上架需要 ICP 备案 + APP 备案（2023-09-26 起，纯离线 App 也要）。
主体和域名已有，**只需新增 APP 备案**。

但备案表要填「云服务 IP 地址」，而实际业务在境外。已知的三种做法：

| | 做法 | 问题 |
|---|---|---|
| A | 备案填境内 IP，业务全跑境外 | **填报与实际不符**；管局抽查发现有注销备案的风险，且会牵连同主体的馋了 |
| B | 境内服务器做 API 网关/中转，境外做存储 | 备案表填的是真实业务 IP；**但数据仍然出境，没解决个人信息跨境问题**；且每次同步多一跳 |
| C | **按敏感度分层**：照片/手账迁到阿里云 OSS（境内），学习进度留 Supabase | 真正减少出境数据；复用馋了现成的 OSS；可增量做。**但学习进度绑定账号，严格讲也算个人信息，风险降低而非清零** |

**当前倾向 C，但不确定它是否足够满足《个人信息保护法》的跨境要求。**

**关键有利条件：现在真实用户约等于零，没有存量数据要迁——这是迁移成本最低的时刻。**

### 决策 2 · 内容包分发（与备案无关，但同样卡大陆）

词库内容包（约 8MB）通过 `raw.githubusercontent.com` 分发。
**开发者本人在国内网络下访问该域名约需 6 秒，完整下载要一两分钟。**
App 顶部因此长期显示「当前使用离线内容」的提示条。

**这意味着即使备案解决了，大陆用户的内容更新体验也是坏的。**
迁到境内 CDN / 阿里云 OSS 是独立于备案的必要项。

### 决策 3 · 时机

已知的工程债（都有工单，正在修）：

- 同步链三处会导致用户数据丢失：云端空表会覆盖本地生词口袋；
  补传途中可能静默新建匿名账号并把数据写进去；删账号时照片可能永久成孤儿
- 词卡对齐显示的中文有一批是错的（已修主要一类，仍有残留）

**当前判断是「先修完同步链，再动存储架构」** —— 在一条已知会丢数据的链上
再叠一层网关或迁移存储，出问题分不清是哪一层。

## 四、想请外部意见的具体问题

1. **方案 C（按敏感度分层）在《个人信息保护法》下够不够？**
   照片和手账迁境内、学习进度留境外，是否仍构成需要单独申报的数据出境？
2. **个人主体（非企业）做这件事有没有额外限制？**
   现有备案主体是个人（自然人）。
3. **APP 备案时「云服务 IP 地址」填阿里云 ECS，而部分业务在 Supabase，
   这个填法是否合规？** 需要在备案材料中说明吗？
4. **有没有比 A/B/C 更合适的第四种做法？**
5. **顺序建议**：是先备案上架、再逐步迁移，还是迁移完再备案？

- 是否要做大陆区（已决定要做）
