# 言 · 词卡内容标准(词场版)

2026-08 定。这份是**内容写法标准**,不是新功能 —— 和「词卡分层释义」同性质。
写词条的人照这个写,不用每次重新讨论。

背景:参考了识日的词卡,取了它的「拓展词」洞察,拒绝了它的词典框架。
下面每条规则后面都写了为什么,因为不写为什么的标准会被下一个人以「看起来更好看」推翻。

---

## 一、例句由词决定,不由产品定位决定

**旅行打卡是入口,不是滤镜。**

言靠旅行吸引用户,但这不意味着背词模块全部为旅行服务 —— 那样知识面会变窄,
而且会造假。`明ける`、`就業`、`辻褄` 硬贴旅行框就是编内容。
N1/N2 那几千条主要服务阅读和备考,给它们套旅行场景,反而降低了它对备考用户的价值。

写例句时问的是「**这个词在真实日语里出现在哪儿**」,不是「怎么把它跟旅行扯上关系」。
旅行/日漫/生活/工作/新闻都可以。紅葉 的例句碰巧是秋天出行,那是因为它真实场景就是那个,
不是因为言是旅行 App。

## 二、意象只给三类词

「核心意象」是好东西,但**给不需要的词配意象就是画蛇添足**。

判断标准很简单:**中文母语者看一眼汉字能不能懂**。能懂的不配意象。

| 配意象 | 为什么 |
|---|---|
| 和语词(もったいない、しみじみ、なんとなく) | 汉字给不了钩子,只能靠画面 |
| 片假名外来词(エリンギ、ニュアンス) | 中文里没有对应物 |
| 汉字词但日语义偏离中文(注文、大丈夫、勉強、迷惑) | 汉字**反而会骗人**,必须点破 |

不配意象:纯汉字同义词(紅葉、温泉、神社、駅)。红叶就是红叶,你多写一句都是噪音。

反面教材(第一版真写过):紅葉 配了「叶子在落之前,把一年攒的颜色一次放完」——
既不准确(是叶绿素退掉、花青素显出来),又没解释任何东西,纯粹是在表演深度。
**读者要问「这是什么意思」的那一句,就是该删的那一句。**

## 三、词场:用一个句子,不用一个格子

词场 = 这个词真实出现时,身边站着哪些词。

**关键规则:不要把词场做成并列的词块。** 第一版做过,失败了 ——
秋(季节)、山(地点)、温泉(同时会做的事)、見頃(要问的词)是**四种不同的关系**,
摊成一个格子等于让用户自己猜关系。用户的原话是「不太理解,相关性在哪」。

正确做法:**写一个句子,让它们同框出现**,关系自己就显形了。

> 秋、山が紅葉する頃、温泉に行く。
> 秋天山变红的时候,去泡温泉。

这句话同时是例句、是词场、是一个可复习单元 —— 一份内容三个用途。

### 词场成员的硬规则

1. **必须能对上词库里已有的词条 id**。写词场的人要对着词库配,不能凭感觉写。
   配不到的:要么补词条,要么换词。
   (第一版又破了这条 —— 配了 `見頃`,而它根本不在词库里,于是点不进去。)
2. 3~5 个,不要更多。多了就变成词典的近义词列表。
3. **不列近义词**。识日给きのこ配了椎茸/松茸/エリンギ 六个蘑菇品种,那是词典;
   而山/森/秋/キノコ狩り 是一个可以站进去的秋天。只要后者。

### 词场那一节的标题跟着词走

不要固定叫「相关词」「一起出现」。用 `wordCards` 里已有的 `relatedLabel` 机制,
每个词自己定:

- 注文 → 「在餐厅还会遇到」
- 紅葉 → 「秋天会一起遇到」

固定标题会逼你把不同关系塞进同一个筐,这正是第一版翻车的原因。

## 四、能进结构化字段的,不要写成散文

用户原话:「是不是在最顶部的词意就可以标上是动词还是名词」。对的,而且更便宜。

第一版把「こうよう 可以当动词用」写成了卡片底部的一段散文。
但 `pos` 字段里本来就有「名词(する动词)」这个取值(46 条在用)——
标对了,那段散文根本不用写。

**规则:先问这条信息有没有对应的字段。有就填字段,没有才写散文。**

同字多读(紅葉 こうよう / もみじ)也不要互相指来指去 —— 两条并列,各自标词性和释义,
用户一眼看完,不会怀疑是自己记错了:

```
紅葉
  もみじ   [名词]          红叶;枫树 —— 叶子本身,多用在诗和名字里
  こうよう [名词・する动词]  (山)变红
```

## 五、注记要具体,不要点评

反面教材:「紅葉狩り 是「猎」红叶。和赏樱一样,在日本是正经的出行理由,不是随便看看。」
用户的评价是「略抽象」。

问题出在后半句 —— 「正经的出行理由」「不是随便看看」都是**点评**,不是事实。
前半句「「猎」红叶」是好的:一个字点破,说完就停。

文化注记的公式仍然是:**具体场景 + 令人意外的规则 + 可执行行为**。
三样缺一样就别写。

## 六、书写形式:跟现实,词条另标汉字

蕎麦 / 御馳走 / お目出度う 这类,日常书写压倒性用假名。
**例句写现实里的写法**(そば / ごちそう / おめでとう),词条头保留汉字并标注常用写法。

理由:用户学到的应该是他在菜单上、招牌上真会看到的形式。

这条有一部分可以机械判定 —— JMdict 的 `uk`(usually written using kana alone)标记。
但注意 2026-08 的验证结果:严格可自动的只有约 229 条,净可直接改约 104 条,
**其余仍然要人判断**。见 `staging/jmdict-join-report.md`。

## 七、词场顺带解决场景标签

紅葉 的词场是秋/山/温泉,那它的场景标签就是这个 —— 不需要再单独打一遍 tag。

这一点很重要,因为 2026-08 的验证证明**场景标签没法自动化**:
JMdict 的 `field` 在 sense-1 上只覆盖 112 条(1.6%),而且偏向 math/comp/Buddh/sumo,
生活场景类的 food 只有 12 条。

所以路线是:**手工精选两三百个词写词场,顺带得到路由信息**,
而不是给 6955 条打标签。见 `staging/tags-plan.md`。

## 成本诚实

一张紅葉卡(找意象、判断哪几个邻居是对的、确认文化点站得住)要认真想很久。
**8298 条按这个深度做是不可能的**,任何声称做完了的产出都是在灌水。

词场是**选出来的两三百个词才有的一层**,不是全库属性。
其余的保持词典状态就好 —— 词典本来就不需要每个词都有灵魂。
