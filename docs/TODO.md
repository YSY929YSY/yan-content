## 上架后

- [ ] **拍实物看重点**(优先级最高的新功能)
      拍菜单/药盒/地铁票/超市标签 → 告诉用户哪几个词必须懂、
      哪些能忽略、下一步做什么。
      · 技术上已建好八成:Edge Function 已有 `kind` 分支,加 `kind:"object"` 即可
      · 它是 `scenePack` 里 `look` 字段(「看什么」)的动态版,不是新概念
      · **红线:输出翻译就废了**。价值全在「哪句可以不看」和「下一步做什么」
- [ ] **「第一次」记录**
      第一次自己办入住、第一次问路……不是连续打卡。
      · 契合「一期一会」:第一次按定义不可重复,刷不出来
      · **红线:不能做成清单**。预置一份"36 个第一次"就退化成打卡任务
      · 正确形态:现场口袋里加一个可完全无视的标记(说出口了),
        「第一次」是这份数据的透镜,不是新数据模型
      · 三条约束:不显示未完成的、不做必答、不统计数量
      · 等上架后做 —— 它需要真实使用数据才设计得对
- [ ] **N3 以上词条人工校对**
      现在 verified 只有 2 条。词书已收敛成 1343 条定稿词,
      剩下 6955 条在搜索里当词典用,不算欺骗,但校对了才能进词书。
- [x] **自定义打卡**(2026-08-03)—— 用户能记任何地方,不再受限于言收录的 43 个。
      地名搜索走 Nominatim(免费无 key、不引原生依赖、不用重打 build),
      存真实经纬度进已有的 `user_places` 表。
      **关键认知**:瓶颈从来不是内容产得慢,是「只能打卡言收录过的地方」这个耦合 ——
      内容从「门槛」变成「奖励」:打卡任何地方都能记,打到收录点会多出一段言的注记。
      副作用:打卡数据将来就是内容优先级的排序依据,不用再拍脑袋决定做哪些点。

- [ ] **地图:矢量 vs 真实(已决策,等行程规划一起做)**
      结论:**两者结合,但不是叠在同一视图里 —— 按缩放级别分工**。
      · 世界足迹(全球视图)= 矢量。街道细节在这个尺度是噪音,
        而且矢量能做成「言的样子」;现在的点阵示意图够用,不是坏方案
      · 行程规划 / 兴趣点(未来)= 真实地图。需要街道、距离、真实位置关系
      选型倾向 **MapLibre GL Native**(`@maplibre/maplibre-react-native`):
      开源无锁定、样式完全可定制(能做近白+teal 的言版地图)、
      同一组件可叠自有矢量图层和真实瓦片、瓦片源可后换可自托管。
      不选 Mapbox(要 key/有配额/样式绑平台),
      不选 react-native-maps + Apple Maps(免费但样式改不了,长得和所有 App 一样)。
      **现在不做的理由**:上架不需要;会引入原生依赖、包体积、地图 SDK 自己的隐私申报、
      可能的配额费用;而且地图长什么样应该由「添加兴趣点」的交互决定,
      先做地图再设计功能=先买锤子再找钉子。
      **已就绪的资产**:43 个地点全都有真实 `{lat,lng}`,
      以后换任何地图库都是纯渲染层改动。行程规划里用户加的兴趣点也要存经纬度,
      不要只存地名 —— 那样接上真实地图时历史数据能直接落到正确位置。

## 已经踩过的坑(别再踩)

- **弱网清空共享账本**:`fetchLedgerData` 失败返回空数组,被当成"账本真的空了"
  → 失败一律返回 `null`,调用方见 `null` 保持现状
- **内容源缩水删打卡记录**:按当前内容过滤 `visitedIds` 再落盘 = 永久删除
  → 记录归用户、显示归内容,两件事分开
- **登录不迁移数据**:匿名 → Apple 是两个 user id,历史进度成孤儿
  → 登录后从本机 AsyncStorage 全量补传
- **发布流水线自锁**:pre-push 钩子校验工作区路径,而发布脚本会先切到 main,
  那个路径在 main 上不存在 → 校验待推送的提交,不校验工作区
- **RLS 建了但没 GRANT**:策略管"哪些行",GRANT 管"能不能碰这张表",
  少了直接 403
- **结清删账目**:让「我花了」和预算跟着归零
  → 只打 `settledAt` 标记,谁欠谁算未结清的、个人花费算全部
