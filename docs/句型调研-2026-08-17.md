## 0. 结论摘要（先说最重要的四件事）

1. **`exp` ≠ 句型。**【实测】JMdict 全量里带 `exp` 词性的条目有 **13,397 条**，但随机抽 15 条看，主体是**谚语、惯用句、固定动词短语**（「兄弟は他人の始まり」「毛を吹いて疵を求む」「破産を申請する」），不是语法点。直接按 `exp` 捞会捞到一堆成语。

2. **点名的 6 个全部查到了，但有两个不在 `exp` 里。**【实测】`ために` 的词性是 `conj`，`のに` 是 `prt`——**只按 `exp` 筛会漏掉这两个**。候选池必须是 `exp + prt + conj + aux + aux-v + aux-adj`（**13,888 条**，实测）。

3. **筛选方案能跑通，落到 553 条。**【实测】用「语法词性 + 表层形长度≥3 + 排除古语/俚语等 misc 标记 + Tatoeba 文档频率 DF≥30」筛，得到 **553 条**，其中已在 wordBank 里的 91 条，**净新增 462 条**。第 5 节给了完整阈值表和可执行步骤。

4. **⚠️ 中文释义没有来源，这是本事的真正瓶颈。**【实测】JMdict 三份全是日英，无中文字段。仓库里唯一的日中词典源 `tools/data/zhwikt-jpn.jsonl`（79,636 行）**一条都覆盖不到**：`にすぎない / しかない / ために / のに / ように / 念のため` 全部 miss，连 `だけ` `ほど` 都没有。**所以「补句型」在数据层面只能补出英文那一半，中文必须逐条人工／AI 生成后人工审。** 详见第 6 节。

**一句话判断**：候选清单可以自动化产出（几小时脚本活），**中文释义是 462 条的人工内容工作量**，这是决定做不做的真正成本项，不是技术问题。

条目结构（实测，字段名不是猜的）：

```json
{
  "id": "1009730",
  "kanji": [{"common": false, "text": "に過ぎない", "tags": []}],
  "kana":  [{"common": false, "text": "にすぎない", "tags": [], "appliesToKanji": [...]}],

     "misc": [], "info": [], "field": [], "dialect": [],

```

要点：
- 词性字段叫 **`sense[].partOfSpeech`**（不是 `pos`），是**每个义项一份**，同一条目不同义项可以不同词性。

- 频率标记：沿用上一轮结论——jmdict-simplified **丢弃了 nf01–nf48 / ichi1 / news1 / spec1 / gai1**，只剩布尔 `common`。本轮未重测这一点（上一轮已逐条扫描 495,901 个表层形确认为 0）。

## 4. 怎么从 21 万条里筛出「初学者真的需要的」

### 4.1 信号一：`common` 布尔字段 —— **对 `exp` 子集依然区分度不足，但方向和上一轮相反**【实测，本轮重测，未沿用上一轮结论】

| 口径 | 有 common 表层形的条目 | 占比 |
|---|---|---|
| 全量 217,625 条 | 22,610 | **10.4%** |
| `exp` 子集 13,397 条 | **445** | **3.3%** |
| `exp/prt/conj/aux*` 池 13,888 条 | 642 | 4.6% |

**重要**：上一轮在 563 条 N5 锚点词上测出 `common=true` 占 93%（几乎无区分度，因为锚点本来就都是常用词）。**在 `exp` 子集上完全不是这个数：只有 3.3%。** 上一轮的结论**不能沿用**，本轮已重测。

- **好处**：`common` 一刀切能把 13,397 → 445，粒度合适。
- **致命问题**：**`にすぎない` 会被切掉**（两个表层形都是 `common=false`）【实测】。而它正是任务书点名的核心例子。
- **结论**：`common` **可以当加分项，不能当硬门槛**。

### 4.2 信号二：Tatoeba 文档频率（DF）—— **主力信号**【实测】

方法（本轮实跑，脚本在 scratchpad，可复现）：
- 对 13,888 条候选池的**全部 kanji/kana 表层形**建 trie，在 `tools/data/tatoeba/jpn_sentences.tsv` 的 **248,758 句**上做多模式子串匹配。
- **句内去重**后计数 → 得到每个表层形的**文档频率 DF**（出现在多少句里），不是 token 频次。
- 一个条目取其所有表层形 DF 的最大值。

阈值扫描【实测】：

| DF 阈值 | 候选池剩余条目 | 其中含 common 表层形 |
|---|---|---|
| ≥0（全部） | 13,888 | 642 |
| ≥1 | 5,335 | 614 |
| ≥5 | 1,959 | 536 |
| ≥10 | 1,413 | 478 |
| ≥20 | 1,020 | 414 |
| ≥50 | 670 | 315 |
| ≥100 | 489 | 255 |
| ≥200 | 352 | 193 |
| ≥500 | 225 | 123 |
| ≥1000 | 163 | 89 |

**DF 在这个子集上分布良好**：`ように` 3,666 / `のに` 2,310 / `ために` 2,015 / `しかない` 143 / `にすぎない` 58 / `念のため` 12。是连续量，能排序，比 `common` 有用得多。

**已知缺陷（实测确认，必须处理）**：裸 DF 的头部被**单假名**污染。DF Top-10 全是 `は(154,775) い(123,960) の(116,911) た(114,503) に(97,542) って(88,593) を(84,843) な(82,934) し(81,326) で(73,066)`。原因是子串匹配对 1–2 字表层形会大量误命中（`記/き` 被算成 DF=29,963 就是纯噪音）。

**修正**：加**表层形最小长度 ≥3 字**的约束。**已抽查验证**这个约束下子串匹配是干净的【实测】——`ように / 念のため / にすぎない` 在 Tatoeba 里的实际命中句都是真用例：

```
ように   → あなたの勉強を邪魔しないようにします。
念のため → 念のためもう一度いいます。
にすぎない → 彼女は歌手にすぎない。
```

### 4.3 信号三：`misc` 标记排除【实测有效】

JMdict 每个义项带 `misc` 数组，可用于排除古语/罕用/粗俗层。排除集：

```
arch obs obsc rare dated hist          （古语/废弃/罕用）
sl m-sl net-sl col fam male-sl chn     （俚语/口语层/儿童语）
vulg X derog joc poet                  （粗俗/贬义/戏谑/诗歌）
id proverb yoji on-mim                 （惯用句/谚语/四字熟语/拟声）
```

`id / proverb / yoji` 这三个是**专门用来剔掉第 2.2 节那类谚语成语的**。

### 4.4 信号四：`jpn_lemma_index.pkl` —— **不适用**

上一轮用的 `tools/data/tatoeba/jpn_lemma_index.pkl`（42,326 个 Sudachi 原形）对**词**有效，但**对句型无效**：`にすぎない` `ために` 这类跨词边界的表达不会成为 Sudachi 的 `dictionary_form()`。所以本轮改用子串 DF。**【实测】**：本轮未逐个验证 lemma index 是否含这 6 个（子串 DF 已经够用，没必要）→ 这一条标为**【未能测得】**，理由是路线已被更好的方案取代，没有花时间。

## 5. 可执行的筛选方案

### 5.1 方案（推荐配置）

```
候选池   = partOfSpeech ∩ {exp, prt, conj, aux, aux-v, aux-adj} ≠ ∅        → 13,888
misc 过滤 = 排除 §4.3 的 20 个标记                                          
长度约束 = 至少一个表层形长度 ≥ 3 字（用于 DF 计算和保留判定）              
频率门槛 = 该条目所有 ≥3 字表层形的 Tatoeba DF 最大值 ≥ 30                  
                                                    ↓
                                              553 条【实测】
```

**产出规模实测网格**（长度约束 × DF 阈值，均已含 misc 过滤）：

| | DF≥10 | DF≥20 | DF≥30 | DF≥50 | DF≥100 | DF≥200 |
|---|---|---|---|---|---|---|
| **长度≥2** | 1,198 | 837 | **677** | 511 | 349 | 234 |
| **长度≥3** | 1,067 | 710 | **553** | 395 | 241 | 143 |
| **长度≥4** | 798 | 490 | **354** | 234 | 123 | 58 |

任务书要求「规模控制在几百条」→ **长度≥3 / DF≥30 → 553 条**是最贴的落点。想更保守用 DF≥50（395 条），想更全用 DF≥20（710 条）。

### 5.2 与现有 wordBank 的重叠【实测】

| 项 | 数量 |
|---|---|
| 筛选结果 | 553 |
| 已在 wordBank（按 `jmdictSeq` 匹配） | 70 |

（wordBank 共 **6,683** 条带 `jmdictSeq`【实测】，占 8,005 的 83.5%，所以 seq 匹配是可靠的去重手段。）

### 5.3 `念のため` 问题：单一阈值会漏掉它

`念のため` DF=12 < 30，**会被刷掉**【实测】。这暴露了纯频率排序的盲点：**低频但高实用**的表达（`念のため` `に応じて` 这类"办事场景高频、语料库低频"的词）。

**建议改成两档**：

| 档 | 规则 | 规模【实测】 |
|---|---|---|
| **A 档（自动入库）** | 长度≥3 + misc 过滤 + **DF≥30** | 553 |
| **B 档（人工挑选池）** | 长度≥3 + misc 过滤 + **10≤DF<30** | 1,067 − 553 = **514** |

B 档 514 条规模可控，人工过一遍能捞回 `念のため`（DF=12）这类。**【推断】**：B 档里值得捞的估计是少数，但**没有实测**，不给具体比例。

### 5.5 管线里必须处理的两个坑【实测发现】

1. **展示形选择**：`misc` 含 `uk`（usually kana）或汉字形带 `rK` 标记时，**必须展示假名形**。实测反例：`ために` 的第一 kanji 形是 `為に`、`呉れる`（实际是 くれる/てくれる）、`就いては`（ついては）、`其れでも`（それでも）、`無しに`（なしに）——**直接取 `kanji[0]` 会给出学习者根本不会见到的写法**。
2. **同假名消歧**：`ように` 有 2 条（1013110 / 2409160「陽に」）。建议规则：同假名多条时取 `common=true` 且 DF 高者；仍并列则人工。

## 6. ⚠️ 中文释义：这条决定可不可行

### 6.1 JMdict 有没有中文？—— **没有**【实测】

三份文件的 `languages` 字段全是 `["eng"]`，`gloss[].lang` 全是 `"eng"`。**零中文。**

### 6.2 仓库里有没有别的日中来源？—— **有一个，但对句型完全无效**【实测】

**`tools/data/zhwikt-jpn.jsonl`**（36,341,374 B，中文维基词典的日语条目）

| 指标 | 实测值 |
|---|---|
| 行数 | 79,636 |
| 去重 headword | 78,129 |
| 带中文释义（`senses[].glosses` 非空）的行 | 77,904 |

词性分布【实测】：

```

romanization 888  adj 360     name 339    character 199   adv 152
syllable 83   phrase 70   suffix 69   adj_noun 65   intj 41
pron 40   particle 38   proverb 29   prefix 21   conj 12   ...
```

**覆盖测试结果（实测，按 headword 精确匹配）**：

| 查询 | 命中 |
|---|---|
| にすぎない | ❌ 0 |
| しかない | ❌ 0 |
| ために | ❌ 0 |
| のに | ❌ 0 |
| ように | ❌ 0 |
| 念のため / 念の為 | ❌ 0 |
| に過ぎない / 為に / 様に | ❌ 0 |
| **だけ**（对照） | ❌ 0 |
| **ほど**（对照） | ❌ 0 |
| 過ぎる（对照，普通动词） | ✅ 1 |

**结论**：zhwikt 是**汉字名词导向**的（70,907 条 `unknown` 抽样看全是「大臣」「法制」「整理」「病気」这类汉字词），**语法层几乎空白**——全库只有 `particle 38 + conj 12 + phrase 70 + proverb 29 ≈ 149 条**，而且连 `だけ` `ほど` 这种最基础的都没有。**对本次需求的覆盖率实测为 0/6。**

（它确实有极少数高质量助词条目，比如 `し`「连接助词，用于连接一系列原因」、`ば`「…ば…ほど：越...，就越...」，带例句和中译。但 38 条 particle 撑不起 462 条的需求。）

### 6.3 其他日中资源盘点【实测】

| 资源 | 内容 | 对句型中文释义有用吗 |
|---|---|---|
| `tools/data/tatoeba/jpn_to_cmn.pkl` | dict，**14,715** 条「日语句 id → 中文译句」 | **只能给例句中译，给不了释义**。且 14,715 / 248,758 = 5.9% 覆盖率 |
| `tools/data/tatoeba/cmn_sentences.tsv` | 87,264 行中文句 | 同上，句子不是释义 |
| `tools/data/tatoeba/align-candidates-n5n4.jsonl` | N5/N4 词的日中例句对齐候选 | 只覆盖已有词，不含句型 |
| `tools/data/kanjium-accents.txt` | 音高重音 | 无关 |
| JMdict ×3 | 日英 | 无中文 |

**仓库里不存在任何可用于句型的日中释义源。**

### 6.4 那「补句型」实际上意味着什么

**可以自动产出的（脚本活，几小时）**：
- 462 条净新增候选的：日语表层形、假名读音、**英文释义（JMdict 直接给，且分义项、带 `info` 接续说明）**、词性、Tatoeba DF 排序、日语例句（从 248,758 句里挑）。

**必须人工／AI 生成 + 人工审的**：
- **462 条的 `meaning_zh`**——**没有任何数据源，一条都拿不到。**
- 例句的中文翻译：`jpn_to_cmn.pkl` 只覆盖 5.9% 的 Tatoeba 句，**【推断】**大部分选中的例句需要另配中译（这个 5.9% 是全库覆盖率实测，不是「选中例句」的覆盖率——后者**【未能测得】**，因为例句还没选）。

**现有 wordBank 的做法就是这个模式**【实测】：`pos=惯用` 的 63 条（`いただきます` `かもしれない` `気に入る` `ごめんなさい`…）**同时有 `meaning_zh` 和 `meaning_en`**，而且 `meaning_en` 明显是 JMdict 原文（`行けない` → "bad; wrong; naughty"，与 JMdict gloss 逐字一致），`meaning_zh` 是自己写的。**所以「英文自动、中文人工」这条路在本项目里已有先例，不是新发明。**

### 6.5 结论

> **可行，但成本不在技术侧。**
> 数据管线能自动把 462 条句型连**英文释义、词性、接续说明、频率排序、日语例句**一起产出；
> **`meaning_zh` 是 462 条纯人工内容工作量，无捷径。**
>
> 有意思的是：任务书的动机本身（「功能词的细微差别上，英文释义比中文更能区分」）在这里变成了优势——
> JMdict 恰好把 `にすぎない = no more than / merely` 和 `しかない = having no choice but to / there is only`、
> `ために = for the sake of` 和 `ように = so that, in order that` 分得清清楚楚，而且 `しかない` 还用 `info` 把「接动词」和「接名词」拆开了。
> **【推断，非实测】**：如果产品接受「句型卡以英文释义为主、中文只写一句简短提示」，人工成本会显著低于按现有 wordBank 标准写完整中文释义。这是个产品决策，不是数据问题。
