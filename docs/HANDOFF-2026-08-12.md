### 三条核心决定

1. **城市是容器,旅行是标签。** 一次旅行横跨几城,一个城市会去很多次;第二次去东京翻开的
   应该是同一本册子。`city_id` 是稳定 id(`city:jp:tokyo`),反查失败落 0.1° 网格 id
   且 `resolved=false`,**照样收下记录**,以后补反查再合并(四处一起改写,见 `remapCityId`)。
2. **「第一次」零新表。** 就是 `moment_tags` 的 `kind='first'`。三条红线落成数据事实:
   没有枚举/seed(不成清单)、发生过才有行(没有「未完成」)、**故意不建按 kind 计数的索引**。
   有一条测试扫导出名,出现 `count`/`streak`/`total` 就红。
3. **页面永不拍平。** 每个元素存「在哪/多大/什么材质/多厚」,光影渲染时算。
   这一条同时解决了层次感、越界(延展到本子外)、和**可打印**(同一份数据换 300dpi 重渲)。

### 声调(pitch accent)—— 有源,已 join(2026-08-13)

`tools/join-pitch-accent.py` + `src/features/wordbank/pitch.js`(纯函数,10 条测试)。

数据:[kanjium](https://github.com/mifunetoshiro/kanjium) `accents.txt`,124,137 词,
**CC-BY-SA 4.0,署名 Uros O.** —— 和 JMdict 同一个许可。
⚠️ **上线前必须加进「关于 → 数据来源」那一屏,并且和言的原创内容分开写。**

**覆盖 7574 / 8047 = 94%**(N5 82% / N4 88% / N3 95% / N2 93% / N1 94%),
格式认不出 0 条、声调位置超出拍数 0 条。产物 `staging/pitch-accent.json`,**未并入内容包**。

为什么值得做(这不是又一个锦上添花):

- **词库里有 207 组「同音但声调不同」,涉及 535 个词条** —— `書く(型1)/欠く(型0)`、
  `紙(型2)/神(型1)`、`箸(1)/橋(2)/端(0)`。在这之前这些卡在 App 里长得一模一样。
- 中文母语者有声调,会**下意识给日语词安一个调**,安错了也没人纠正。这是真缺口。
- 它是 join 不是创作:抄完能机器验,不需要懂日语的人拍板。

三条实现上的坑,都写进 `pitch.js` 了:

1. **拍不是字符。**「きゃ」一拍,「っ」「ん」「ー」各一拍。算错整条高低线就错位。
2. **型0 和「型=拍数」在词本身上完全一样**(`はな` 平板 vs 尾高 都是「低高」),
   只有后接助词能分开。所以 `pitchPattern` 必须同时返回 `particleHigh`,
   界面上也不能假装这两个分开了。
3. **10% 的词有多个声调型**(`明るい(0,3)`),**只显示第一个**。
   把「0,3」摆给学习者,是把一道他无法处理的选择题丢给他。

**⚠️ 一个方法论教训:第一版跑出来覆盖率 85%,是 join 写错造出来的假数字** ——
kanjium 对纯假名词的 `読み` 列是空的(`アパート \t \t 2`),995 个假名词条一条没进来。
85% 和 94% 都「看起来合理」,不去看漏掉的名单就发现不了。**别只看比例,看名单。**

### coreChunk 候选管线(2026-08-13,已跑通,但见上面那条分界)

`tools/build-corechunk-candidates.py`。**只出候选,不写内容**,产物在 `staging/`。

语料是**已经在本地的** Tatoeba 24.8 万句(CC-BY 2.0 FR)+ 已缓存的 Sudachi 原形索引,
零下载成本。按词性抽相邻型式(`N+助+V` / `N+は+A` / `A+N` / `N+の+N` / `Adv+V`),
按频次排,每条带一句真实出处。

**N3 结果**:1630 个缺搭配的词 → **1012 个出了候选**(语料不足 228 / 抽不到 365 / 词性不支持 25),
跑完 15 秒。

两条调过的参数,都是看了输出才定的:

- **サ变(`議論する`)降到末位。** 它几乎总是频次榜首,但信息量接近零 ——
  「这是个する动词」是语法事实,`pos` 字段里本来就有这个取值(标准第四节)。
  占着榜首会把 `議論を始める` 这种真搭配挤下去。不删,因为有 135 个词确实只有这一种用法。
- **频次 < 3 一律丢。** 频次 2 的样本清一色是噪声(`金持ちの商人` / `哲学は難しい` /
  `犬は嬉しい`)—— 那不是搭配,是碰巧同句。代价是候选数从 1179 降到 1012,值得。
- 固有名词和数词不当伙伴词:Tatoeba 满篇 Tom 和 Mary,不挡的话 `会う` 的前三名是
  「トムに会う」「メアリーに会う」。挡掉之后第一名是「友達に会う」。

**对着人写的 1763 条搭配做过命中检验:Top-1 24% / Top-5 39%。**

## 五、这一轮新增的硬规矩(老文档里没有)

1. **装原生依赖必须查 peerDependencies。** 装 Skia 时没查,它把 reanimated 标成
   `optional: true` —— 装得上、测试全绿、**只有真机上 JS 一加载就抛**。
   代价是白打一次 EAS 包。原生依赖要**攒着一次装**(这次补装 reanimated 时
   顺手把 gesture-handler 也装了,因为拖拽迟早要用)。

   **1b(2026-08-12 补,是 1 的变体,又栽了一次):危险的不是「装」,是「第一次真正 import」。**
   gesture-handler 在 `package.json` 里躺了很久,但**全项目没有一行代码 import 过它**。
   写手势那天第一次 import,失败形状和 Skia 那次一模一样:装得上、`npm test` 全绿、
   eslint 干净,**而手机上那个 dev client 是在装它之前打的包,里面没有这个原生模块,
   JS 一加载就抛**。原规矩说的是「装的时候」,盖不住这种「装了很久没用过」的情况。

   **判据换成:改动是否让某个原生模块第一次进入 JS 的加载路径。** 是的话
   `eas build --profile development` 重打,别指望本地能测出来 —— 本地什么都测不出来,
   这正是这个坑每次都能得手的原因。
2. **单行 TextInput 绝对不要设 `lineHeight`。** iOS 上一设,文字按行高盒子底部对齐,
   字沉到框底。正确配方 `SINGLE_LINE_INPUT`(paddingVertical:0 + textAlignVertical +
   includeFontPadding:false)。这个毛病出现过四次(备注/预算/邀请码/金额)。
   **金额输入框是唯一例外**,它的 lineHeight 是真机调过的,注释里标了「别顺手统一掉」。
3. **占位符不要混排货币符号和中文。** iOS 按字形回退字体,中文那半截用另一套度量,
   基线被拉低 —— 看起来就是「没居中」。标签放框外,占位符只放纯 ASCII。
4. **异步图片没到位之前整页不画。** Skia 每帧照画,`useImage` 是异步的,
   于是用户看到「空 → 纯色块 → 纹理 → 元素落下」一段丑陋过场。用户原话:
   「你做了个动画」。一页纸不该有出场动画。
5. **工具的价值是找出可疑处,不是替人判断。** 罗马音那次:一个准确率 0% 的告警器
   不是第二来源,是噪声源 —— 报十次错九次是它自己错,人第三次就开始无视它。
   **宁可空着不要猜**:补错的词源比没有词源坏得多,它教一个假钩子而用户无从判断。
6. **同一个东西不要写两遍。** 这个文件里两个预算编辑器各有一份 JSX,
   导致修复只落在其中一处;输入框的垂直居中也是各修各的。都已合并。
   (2026-08-13 又合了一处:货币托盘原来有三份 —— 记账/预算/结算。)

7. **本机文件不要存绝对路径(2026-08-13)。** iOS 的 `documentDirectory` 是
   `.../Application/{容器UUID}/Documents/`,那个 **UUID 重装之后会换**。
   存绝对路径 = 隔一次重装,页面上一张永久裂图。
   **存下来的那串只当文件名用,目录每次现拼**(`journalModel.assetUriIn`,有测试)。
   这和打卡照片 `portablePath` 是同一个坑的本地版本。
   写这个函数时我自己又踩了一次相邻的坑:目录路径被当成文件名,拼出一条查无此物的路径 ——
   **拼错的路径比空值坏**,空值调用方会回退,假路径它会当真。测试抓住了。

8. **`render` 里不要裸调原生方法(2026-08-13)。** Skia 的 `image.height()` 在图片
   失效后会抛,而它当时在 `render` 里 —— 一抛就是整棵子树卸载,屏幕上只剩一块
   **和背景同色**的空白,看不出发生过任何事。已经包起来:拿不到长宽比就少画一个元素,
   不把整页拖下水。

9. **「还没画」和「画不出来」必须在界面上分得开(2026-08-13)。**
   `JournalPage` 的 `ready` 门是对的(一页纸不该有出场动画),但它让加载中和加载失败
   长得一模一样。生产环境保持原样,**预演屏加了 `onReadyChange`**,白屏时直接写出
   「纸(kraft-bag)未到」还是「已到」。排查全靠这一行,不然只能靠猜。

## 六、用户的产品判断(这一轮说的,不要推翻)

- **手账要放在「世界打卡」里**,不是跟全局并列的东西
- **手账不能叫「账」** —— 单字读成账单。手账和分账是两回事
- **对开是「翻阅」的形态,不是编辑的形态**(手机上一页只剩 ~170pt,点不准)
- **词书不完全为旅游服务**,旅游只是特色。这条**已经写在内容标准第一节**了
- **一个词 = 一张卡**(不管几个读音、几个义项、几个词场);不同的词 = 不同的卡
- **「花里胡哨的是锦上添花,但一定要准确的」**
- 远期:**对标多邻国,做全语种 + 语种间融会贯通**。
  我的分析:多邻国每加一门语言是孤岛,言按共享节点建则加第 n 门会给前 n-1 门增值。
  **但这个优势只在有第二门语言后存在**,所以用户说的「先靠打卡吸引用户」顺序是对的

## 七点五、写禁令的时候要写清它防的是什么(2026-08-13)

**所以这份文档里所有「别做」都要带理由,而且要说清是「暂时」还是「永远」。**

## 九、词库去重:人工复核已完成(2026-08-12),结论是**合并不是删除**

- 例句挑更准的那条
