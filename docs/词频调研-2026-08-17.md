## 0. 结论摘要（先说最重要的三件事）

1. **原计划的路走不通。** 本地三份 JMdict 全是 `jmdict-simplified` JSON 格式，**该格式把 `ichi1/news1/spec1/gai1/nf01–nf48` 全部丢弃了**，只留下一个布尔字段 `common`。已对全部 495,901 个表层形逐个扫描确认：`nf`/`ichi`/`news`/`spec`/`gai` 标记出现 **0 次**。所以「join 一次就能补出 nf01–nf48」这个前提**不成立**。
2. **就算拿到 `common` 也没用。** 563 条 `kanji_anchor` 里 **556 条 `common=true`**，只有 7 条 false。二值标记在 N5 锚点词这个区段上几乎完全不分辨——它无法给出学习顺序。
3. **真正可用的本地频率源是 Tatoeba 语料库**（`tools/data/tatoeba/`，已在仓库里）。它给出连续的文档频率（DF），在 563 条锚点上分布良好（中位数 248，最大 26,526）。本报告第 5 节的排序就是用它实测出来的。

**另外一个必须记下的事实**：563 条锚点词里**只有 19 条带 `jmdictSeq`**。哪怕 JMdict 那条路通了，也只能覆盖 3.4% 的锚点。锚点词必须走 word+reading 反查。

## 4. 优先级标记怎么转成可用排序

### 4.1 原计划的映射方案（**本地数据不支持，需下载才能执行**）

如果拿到原始 JMdict XML，标准做法是：

```
rank_score:
  nf01..nf48  →  freq_band = nf 数字（1 最高频，48 最低频）
                 依据：JMdict 的 nfXX 是把「按语料词频降序排列的词表」每 500 词切一段，
                       nf01 = 第 1–500 名，nf02 = 第 501–1000 名，……nf48 = 第 23501–24000 名。
                       所以 nf 号本身就是一个等距的频次分档，直接当序数用即可。
  无 nf 但有 ichi1/news1/spec1/gai1  →  freq_band = 49（"常用但未进 24000 词表"）
  仅 ichi2/news2/spec2/gai2          →  freq_band = 50
  什么都没有                          →  freq_band = 99
最终排序键 = (freq_band asc, 次级键)
```

> 上述 nf 分档语义（每档 500 词、按语料频次降序切段）是 **JMdict 官方文档的定义，属于既有知识，本次未在本地验证**（本地无 XML 可查）。**标为推断。**

**要执行它必须下载**：
- 文件：`JMdict_e.gz`（EDRDG 官方，http://ftp.edrdg.org/pub/Nihongo/JMdict_e.gz）；或 `scriptin/jmdict-simplified` 的 GitHub Release 里**不提供**该字段，必须回到原始 XML。
- 体积：**未实测**（本地无该文件，本轮未下载）。经验量级约 20 MB 压缩 / 100+ MB 解压 —— **这是推断，下载前应先 `curl -I` 确认。**
- 许可证：**CC BY-SA 4.0（EDRDG）**，与仓库现有 JMdict 产物同源同证，无新增合规问题。

### 4.2 推荐方案：Tatoeba DF（**本地即可执行，本报告已实测**）

排序键 = 该词在 248,758 句 Tatoeba 日语句中出现过的**句数**。

**563 条锚点上的实测分布**：

| DF 区间 | 条数 |
|---|---|
| ≥ 1000 | 90 |
| 300–999 | 173 |
| 100–299 | 153 |
| 30–99 | 75 |
| 1–29 | 41 |
| **0** | **31** |

最大 26,526（私），中位数 248。**分布连续、跨三个数量级，完全够做学习排序。**

**全库覆盖率实测**：8,005 条中 7,432 条 DF>0，573 条 DF=0。

### 4.3 DF=0 的 31 条锚点：是查法问题，不是词冷门（实测证实）

DF=0 名单：
`五日 五つ お菓子 お酒 お皿 伯母さん;叔母さん お風呂 お弁当 下さい 九日 九つ さ来年 誰か 十日 七つ 七日 二十日 一つ 一月 昼御飯 二つ 二日 三日 三つ 皆さん 六日 六つ 八つ 八日 四日 四つ`

一眼可见全是高频词。实测根因（探针查询 lemma index）：

| 词库写法 | lemma index 命中 | 原因 |
|---|---|---|
| `一つ` / `ひとつ` | 0 / 0 | Sudachi SplitMode.C 仍切成 `一`(2,371) + `つ`(1,491) |
| `下さい` / `ください` | 0 / 0 | 原形归一到 `くださる`(3,599) |
| `お酒` | 0 | 原形归一到 `酒`(282)，敬语前缀被剥 |
| `二日` / `ふつか` | 0 / 0 | 数字+助数词被切开 |
| `皆さん` / `みなさん` | 0 / 0 | 切成 `皆`+`さん` |

**两级修复（已实测）**：
1. 剥 `お/ご` 前缀 + 按 `;` 拆异形再查 → **31 条中恢复 5 条**，余 26 条。
2. 对余下 26 条**直接在 `jpn_sentences.tsv` 上做原串子串计数** → **26 条全部恢复**，实测值：
   `下さい 1254`（`ください 3492`）、`誰か 628`、`一つ 535`、`二つ 203`、`皆さん 96`、`三日 75`、`昼ご飯 64`、`二日 55`、`三つ 38`、`四つ 31`、`叔母さん 35`、`一月 19`、`五つ 14`、`十日 13`、`八つ 11`、`五日 10`、`八日 6`、`再来年 6`、`七日 5`、`二十日 5`、`四日 5`、`七つ 4`、`六日 4`、`六つ 4`、`九つ 3`、`九日 2`
   （`伯母さん`/`さ来年`/`昼御飯` 本体 0，但其异写 `叔母さん`/`再来年`/`昼ご飯` 有值）

→ **两级法可让 563 条锚点达到 100% 有 DF 值。**

### 4.4 已知偏差（必须写进方案，不能装作没有）

- **助数词继承基词的 DF**：`～人(～じん)`、`～人(～にん)` 和 `人(ひと)` 拿到同一个 6,423；`～時/～中/～本/～時間` 同理。因为归一化把 `～` 剥掉后就变成了基词。**这不是真实的助数词频率。** 修法：助数词单独按「数字+该字」模式在原句上正则计数，或干脆把 30 条 `～` 词从频率排序里摘出来单独处理。
- **子串计数会误命中**：`一月` 的 19 次里可能混入 `十一月`。子串法只用于 lemma 法失败的兜底，且需人工过一遍。
- **Tatoeba 语料偏日常会话**，对书面/商务词会系统性低估。作为 N5 锚点排序足够，推到 N2/N1 时要重新评估。

## 5. 563 条锚点词：现有顺序 vs 频率排序

### 5.1 现有顺序是什么（实测）

`kanji_anchor` 的 563 条**全部是 N5**（实测 level 分布：N5 = 563，无其他）。

文件内顺序实测为：**先 30 条 `～` 开头的助数词/接尾词块，再 533 条普通词**。两块各自大致按假名五十音排（533 条中相邻逆序对 32/532，属于五十音序与 Python 码点序的差异，肉眼核对 `あう→あお→あおい→あか→あかい→あかるい→あき…` 确认是五十音序）。

## 6. 具体落地方案

### 6.1 建议写入的字段

在每条 wordBank 词上加（**本轮不写**）：

```jsonc
"freq": {
  "src": "tatoeba-lemma" | "tatoeba-substr" | "none",
  "df": 3391,          // 出现句数
  "rank": 14,          // 在本 level 内的降序名次
  "band": 2            // 1..6 分档，见下
}
```

`band` 建议按 4.2 的实测分布切（这样每档规模可控）：
`band1: DF≥1000（90条）｜band2: 300–999（173）｜band3: 100–299（153）｜band4: 30–99（75）｜band5: 1–29（41）｜band6: 0/未知`

**不要**把 `common` 写进去——93% 都是 true，只是噪声。

### 6.2 脚本骨架（`tools/backfill-frequency.py`，本轮未创建）

```python
# 1. 载入
#    - content.fallback.json（只读）
#    - tools/data/tatoeba/jpn_lemma_index.pkl        → lemma -> [sid]
#    - tools/data/tatoeba/jpn_sentences.tsv          → 兜底子串计数用
#    - tools/data/jmdict-eng-full.json               → 仅用于反查 seq / 取异形，不取频率
#
# 2. 为每条词生成候选查询形（顺序即优先级）：
#    a. word 去 ～、按 [;；/] 拆多形
#    b. 剥 お/ご 前缀

```

### 6.3 建议的执行顺序

1. **先跑 report-only 版**，人工抽检 top100 / bottom100 / 全部 `src="substr"` 的条目。
2. 助数词 30 条单独定方案（继承基词频率是错的，但「按数字+字」计数也未必对——可能干脆不给助数词排频率，改用教学序）。
3. 抽检过了再写回，且**只写 `freq` 新字段，不动任何既有字段**。
4. 顺带（**单独工单，不要混在一起**）：3.2 那 1,174 条高置信反查结果可回填 `jmdictSeq`，把带 seq 的比例从 83.5% 提到 98.1%。

### 6.4 要不要下载原始 JMdict XML？

**建议：暂不下载。** 理由：
- nf01–nf48 只覆盖 24,000 词，而且是**按新闻语料**切的分档，对 N5 日常会话词的分辨力未必比 Tatoeba DF 好。
- nf 是 48 个离散档，Tatoeba DF 是连续值，后者排序更细。
- 本地零成本、许可证已合规、已实测可用。

**若之后仍要下载**，需先确认：URL `http://ftp.edrdg.org/pub/Nihongo/JMdict_e.gz`、实际体积（**本次未实测**）、许可证 CC BY-SA 4.0。可以把 nf 档作为 Tatoeba DF 的**交叉校验**（两者严重不一致的词拎出来人工看），而不是替代。
