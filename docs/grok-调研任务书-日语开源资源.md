# 调研任务书:日语学习的开源数据与工具生态

## 背景(请先读,它决定了什么算"有用")

我在做一个日语学习 App,面向**中文母语者**。关键约束:

- **开发者本人不懂日语。** 所以任何内容都必须有**可核对的权威来源**,不能靠"自己审一遍"。
- 一个人开发,没有内容团队。**能脚本化的才可行,需要大规模人工审校的一律不可行。**
- 产品定位是**词汇 + 发音**,**不做语法教学**(因为语法无法从数据源搬运,错了没人看得出来)。
- 已有:8005 条词库(JMdict 血统,带 JLPT 分级)、7510 条音调数据(kanjium × zh.wiktionary × UniDic 交叉验证)。

**所以我要的不是"学日语的建议",是可下载、可核对、许可证清楚的数据和工具。**

---

## 请回答的六组问题

### 1. ⭐ 中日同形异义词(false friends / 同形異義語)—— 最高优先级

中文母语者读日语汉字词时,大部分能直接猜对意思,但有一批会猜错(手紙=信不是手纸、汽車=火车、勉強=学习、大丈夫=没关系、娘=女儿)。

**我需要一份尽可能完整的「中日同形异义词」清单。**

请找:
- GitHub 上有没有这类开源数据集?(关键词:同形異義語、中日同形词、false friends Chinese Japanese、日中同形異義語)
- 学术资源:有没有公开发表的词表(语言学论文附录、教学研究、CC 许可的语料)?
- 有没有词典类项目在词条上标注了这个属性?
- 反向的也要:**同形同义**词表(可以直接迁移语义的),如果存在。

**对每个来源请给出:仓库/URL、数据规模、格式、许可证、最后更新时间、是否可商用。**

为什么最重要:我打算给"你已经认识这个词"打标签,而**误标一个同形异义词,毁掉的正是产品的信任基础**。所以扩标必须是白名单逻辑(在权威排除表之外才是候选),不能是"字形相同就算"。

### 2. 开源词典 / 词汇数据

请覆盖并对比:
- **JMdict / EDICT**(我已在用)、**KANJIDIC2**、**JMnedict**
- **kanjium**(音调,已在用)、**UniDic**(已在用)、**NHK 日本語発音アクセント辞典**(应该不开源,请确认)
- **Tatoeba**(例句,CC-BY)——请说明日中对照句对的实际数量和质量
- **Core 2k/6k**、**JLPT 词表**、**教育漢字/常用漢字**表的开源版本及许可
- **词频表**:有哪些公开的日语词频语料(新闻/口语/字幕/小说分开的更好)?
- 有没有**日中**(不是日英)释义的开源词典?这是我最缺的——现有中文释义大多是机器翻译过来的。

### 3. 音频与发音

- 有没有**开源/CC 许可的日语单词发音音频库**?(如 Forvo 的许可情况、JapanesePod101 的许可情况、有没有 CC 的 TTS 语料)
- 开源日语 TTS 现状,以及**能不能正确读出音调**(这是关键——普通 TTS 读不对アクセント)
- 有没有开源的**音调标注/预测**工具(如 OpenJTalk、pyopenjtalk 的 accent 输出质量如何)

### 4. 开源学习工具:值得借鉴的结构

不是让我抄代码,是想看**数据模型和学习算法**怎么设计:
- **Anki**(FSRS 算法现状 vs 传统 SM-2/Leitner)、**jpdb**、**Yomitan/Yomichan**、**Migaku**、**Renshuu**
- 特别想知道:**FSRS** 现在成熟到什么程度?值不值得从 Leitner 换过去?有没有可直接用的 JS/TS 实现?
- 有没有开源项目做了**「按已知母语锚点排序词表」**这件事?(即:根据学习者母语,决定哪些词最容易先学)

### 5. 教学法(只要有证据的)

我不做语法教学,但想知道边界在哪:
- 有没有**针对汉字圈学习者**的日语教学研究?(中文母语者的日语习得路径和英语母语者差异有多大,有没有量化研究)
- **音调(pitch accent)** 在实际交流中的重要性,有没有实证研究?值不值得作为核心卖点?
- 词汇量与实际能力的对应关系:掌握多少词能应付旅行/日常/新闻?有没有可引用的数据?

### 6. 竞品的**数据侧**现状

不要功能列表,我要的是:
- 哪些日语 App **标注了音调**?(尤其中文市场的)
- 哪些**利用了中文母语者的汉字优势**?还是都在照搬英语向课程?
- 有没有产品做**跨语言词源**(同一词根串起中/日/英/西)?

## 输出格式要求

**每一条资源请给出这七项**,缺项请明确写"未知":

```
名称 | 链接 | 数据规模 | 格式 | 许可证 | 最后更新 | 能否商用
```

然后用一段话说明:**它解决我上面哪个具体问题,以及有什么坑。**

## 三条硬要求

1. **许可证必须查证,不要猜。** 这个项目要商用发布,许可证错了是法律风险。CC-BY-SA 的传染性、GPL 对数据的适用性,请特别说明。
2. **给链接,不要只给名字。** 我要能直接点进去核对。
3. **明确区分「你验证过存在」和「你记得有这么个东西」。** 后者请标注为待核实。宁可少给几条,不要给我一个不存在的仓库地址。
