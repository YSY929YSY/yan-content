## 3. 这一轮学到的三条,别丢

### ① 断言的阈值不能取自被测的常量

角度断言第一版写的是 `|rotation| >= JITTER.minMagnitude`——把那个常量改成 0,断言就变成 `>= 0`,**26 条测试照样全绿**。改成字面量后同样的篡改会挂 2 条。

**每加一条关键断言就篡改一次实现,看它会不会挂。** 这一轮靠它抓到三次假绿。

### ② 有些错误,常规测试在原理上就抓不到

真机上手账拖动/双指/松手**全废**,而当时 21 条测试全绿、tsc 0 错误、eslint 0 error:

```
[Worklets] Tried to synchronously call a non-worklet function `clampScale`
```

测试在 JS 线程跑,`'worklet'` 在那里只是一句无害的字符串。
补了 `src/lib/__tests__/worklet-guard.test.ts`(读源码做静态检查)。
⚠️ **那个护栏的检测函数第一版是假的**(正则跨过函数边界),三条护栏全是假绿——是里面那条「测测试工具」的自检抓到的。

第二个 bug(手势 `Exclusive` 顺序错)**连静态检查都补不了**,只有真机能验。

### ③ subagent 会把上游的错误照单执行

词频那个 agent 按调研的配方跑,发现 top 是 `歯(は) 153587 / 二(に) 86372`——**全是助词的频率**。真实的 `歯` 只有 173,虚高 888 倍。

它自己发现并修正了(DF 是**按写法**统计的,拿假名读音去查等于在数另一个词)。**但如果它照做就交,排出来的东西看起来完全合理,没人会怀疑。**

**每个 subagent 的任务书里都要写:「每个数字必须真跑,拿不到就写『未能测得』,不要估一个数填上。」**
